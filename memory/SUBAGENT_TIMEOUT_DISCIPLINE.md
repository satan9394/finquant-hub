# 后台任务与子代理超时管理纪律（30 分钟节拍）

> 经验文件 · 长期记忆 · 2026-09-13 用户明令：后台任务/子代理不能无限挂起。
> 目的：把"等待感"压到可预期，出问题早发现早处理，不在无意义的轮询/等待上耗会话时间。

## 硬性节拍（用户指定）

1. **后台任务（pwsh 等 job）**：启动后 **30 分钟必检查一次**；检查发现情况出问题（报错、挂起、无输出且 CPU 不动）→ **直接杀死**，然后诊断根因（是该命令本身卡死、还是环境问题如 no_proxy/端口占用）。
2. **子代理（subagent）**：同样 **30 分钟节拍** 检查是否出问题；**个别确需长任务的最长等到 1 小时**再确认一次；超过仍未交付且无进展 → 中断（interrupt_agent）+ 下指令校正或重派。
3. 检查时**不重复轮询**——只用一次有效检查（list_agents / job_list + 工作树信号 / 进程 CPU 采样），得不出结论就用 send_message 直接向子代理要一句话进度，别再空转。

## 检查做法（30 分钟到点时）

| 步骤 | 做法 |
|---|---|
| 1. 看状态 | `list_agents`（子代理 running/ready/idle?）、`job_list`（job running/completed?） |
| 2. 看产物 | git status 是否有新改动/新文件（在做事 vs 卡住） |
| 3. 看活跃度 | 后台命令：查进程 CPU Δ（15s 采样 >0.3 秒=在跑）；子代理：读其 session 尾部最近 tool/call |
| 4. 判断 | 有进展→继续等（再一个节拍）；无进展/报错→处置 |

## 处置（出问题时）

- **后台 job 卡死/报错**：`job_kill` → 跑针对性命令复现根因 → 修环境或重跑。
- **子代理卡住**（如卡在 ask_user_question、循环重试）：`interrupt_agent` 打断 → `send_message` 下明确裁决/校正指令 → 让它继续或重派。
- **子代理交付但门禁未跑全**：指挥（本会话）在有权环境补跑关键门禁再合入；纯文档/低风险改动可基于已完成验证合入并如实标注。

## 与 token 纪律的关系

这是 `MAIN_SESSION_TOKEN_DISCIPLINE.md` 的姊妹条款：不做无意义轮询（省主会话 token），该等时等、该杀时杀（省墙钟时间）。

## 一句话总结

> 30 分钟一检查、出问题就杀、长任务最多 1 小时；检查靠"一次有效探针 + 直接问"而不是反复轮询。
