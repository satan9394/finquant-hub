## 1. 产品定位

**一句话定义**：面向中文个人投资者的本地部署全栈量化投研系统，覆盖 A/港股/美股。

**核心差异化**：
- 本地部署（LOCAL_ONLY_MODE），数据不出本机
- 多 Agent 并行研究 + 13 个本地工具的 function calling
- 52 张 SQLite 表的完整数据闭环（行情→研究→论文→回测→组合→预警）
- 无密码邮箱认证 + Fernet 凭据加密
- 6 条 SSE 流式管线，7 个公开 SSE 端点

**目标用户**：非技术背景的中文金融/投资用户（但实际功能深度已超出"非技术"范畴）

**技术栈**：FastAPI + aiosqlite (WAL) + React 18 + Ant Design 5 + lightweight-charts + DeepSeek API

## 4. 用户旅程

### 4.1 用户 A：投资小白

**目标**："我想知道某家公司值不值得研究"

**进入路径**：
1. 打开浏览器 → `localhost:5173`
2. 本地模式自动登录（或邮箱验证码登录）
3. 看到「今日概览」页面

**操作步骤**（约 5 次关键点击）：
1. 看到首页「任务发射台」→ 点击"分析股票"卡片（带"试用 600519"按钮）
2. 跳转到 `/research` → 输入框已示范"AAPL、600519、00700.HK"
3. 搜索标的 → 点击"打开研究页" → `/research/600519`
4. 看到"选择 AI 研究方式"三卡（快速问答/深度研究/多视角审查）→ 选"深度研究"
5. 等待 4 张 Agent 卡逐个转态 → 阅读报告

**遇到的问题**：
- 首页 `LocalCapabilityBanner` 出现"模型未配置/连通性未验证"技术警告，小白不知是否要先配模型
- 首页统计卡"模型总数/会话数/消息数"是系统内部指标，对小白无意义
- 三选一"快速问答/深度研究/多视角审查"术语生硬，需靠"耗时/额度"标签猜
- 报告中 FACT/MODEL_OUTPUT/INFERENCE 标签、provider 名、as_of 时间戳不理解
- 分析完成后**无"加入自选/组合"按钮**，需绕回首页

**不知道什么**：TTM、FACT/MODEL_OUTPUT/INFERENCE、复权、筹码分布、Bootstrap/Monte Carlo、市盈率/市净率含义、provider、UNKNOWN

**需要什么帮助**：
- 一个明确"这家公司是否值得研究"的通俗结论（有：综合评分/信号结论，但藏在"刷新分析"后）
- "加入自选/收藏"的一键动作（缺失）
- 术语 hover 解释

**产品是否为其设计**：❌ **并非核心对象** — 虽有任务发射台/试用 600519/意图向导等新手引导，但首页技术警告、系统统计卡、证据标签、A 股专业概念密集，A 属于"靠引导勉强可用但极易困惑"。产品实际是"专业投研工具套了一层新手入口"。

### 4.2 用户 B：普通投资者

**目标**："我要研究一家公司并决定是否加入股票池"

**完整流程**（约 7-9 步，但末端断裂）：
1. 打开产品 → `/` → 快速个股分析框搜索"贵州茅台"或"600519"
2. 跳转 `/analysis/600519` → 查看行情条（价/涨跌/PE/PB/市值）+ K 线图
3. 自动触发技术分析报告 → 阅读 13 章 + 综合评分（-100~+100）
4. 查看 SignalInterpretation 信号解读（偏强/偏弱/中性）
5. **卡住** — 想加入自选但分析页无此按钮；想去组合但需手动填代码
6. 绕到 `/portfolio` → 新建组合 → 添加持仓（code/名称/股数/成本价）
7. 查看盈亏/配置分布/风险工作台

**关键断点**：
- **最大断裂**：分析/研究页没有"加入自选/加入组合"按钮（自选仅 Dashboard localStorage）
- 评分藏在报告正文，不是独立仪表
- 自选股存 localStorage，换浏览器即丢

**可能找不到**：评分（藏在分析正文）、加自选（仅 Dashboard）、预警联动（从 Thesis 才能一键建）

**产品是否为其设计**：⚠️ **部分是** — 有组合/预警/自选/研究意图分流，但"研究→入池/入组合"闭环断点、评分弱化、自选本地化，说明 B 是"次优"目标。

### 4.3 用户 C：专业投资者

**目标**："我要建立策略并管理组合"

**完整流程**（约 12-16 步横跨 6 模块）：
1. 打开产品 → `/` → 市场雷达扫描异动
2. `/screening` 选股器筛选候选标的
3. `/alpha` Alpha 因子库搜索有效因子 → 本地模拟 IC/ICIR
4. `/research/:symbol` 深入研究 → Swarm 四大师多角度研究
5. `/strategy-lab` 建立 MA 双均线回测 → Bootstrap/MC/WF 稳健性验证
6. `/thesis` 投资论文 → AI 挑战最强反证 → 漂移核验
7. `/portfolio` 组合管理 → PAPER 模拟账本 → 假设复盘
8. `/alerts` 预警中心 → 技术信号 + 对象监控
9. `/discussion` 多视角审查 → 多 Agent 辩论
10. 定时研究自动定期复盘 → 决策收件箱跟踪待办

**关键差异**：
- 能理解并使用所有专业功能
- 需要因子级别的量化分析
- 需要统计验证（Bootstrap/MC/WF）
- 需要组合级别的风险控制

**可能找不到**：Swarm 藏在"高级：运行投研团队"折叠里；Alpha 搜索藏在底部卡片；比较工作区入口在菜单中部

**产品是否为其设计**：✅ **明确是** — 证据 provenance、稳健性验证、模拟账本、论文追踪、私有分享预览都是专业级资产。

## 5. 页面分析

### 5.1 今日概览 (`/`)

**目标**：市场全景 + 决策入口
**用户是谁**：所有用户
**用户为什么进入**：了解今日市场情况，决定下一步行动
**用户完成什么任务**：查看指数、涨跌统计、行业排行、自选股、决策收件箱

**输入**：
- 自选股列表（本地存储）
- 市场数据（实时 API）

**输出**：
- 主要指数快照
- A 股涨跌统计
- 行业/概念排行
- 人气股排行
- 涨停池
- 决策收件箱

**AI 能力**：
- 大盘复盘（`/api/market/reviews`）— LLM 综合分析
- 决策收件箱（`/api/dashboard/decision-inbox`）— AI 推荐下一步

**数据依赖**：腾讯/新浪/东方财富/Yahoo 行情

**信息密度**：🔴 高 — 首页承载了指数、涨跌、行业、人气、涨停、自选、决策 7 个区块
**新用户理解成本**：🔴 高 — 信息过载，不知道从哪里看起
**专业术语障碍**：🟡 中 — "涨停池""封板""连板""概念板块"需要解释
**操作路径长度**：1-3 步（查看→跳转）
**AI 产品习惯符合度**：🟡 中 — 传统仪表盘风格，不是 AI-first 设计
**ChatGPT/Claude 交互逻辑符合度**：🔴 低 — 没有对话式入口，信息被动展示

### 5.2 研究工作区 (`/research`)

**目标**：个股深度研究的统一工作台

## 6. UX 问题分析

### 6.1 🔴 P0：研究→入池/入组合闭环断裂

**问题**：个股分析页（`/analysis/:ticker`）和研究工作区（`/research/:symbol`）都没有"加入自选股"或"加入组合"按钮。自选股仅存在于 Dashboard 的 localStorage 中。

**影响**：普通投资者（用户 B）研究完一家公司后，无法直接加入自选或组合，需要绕回 Dashboard 或手动去 Portfolio 填代码。这是用户 B 核心闭环的最大断裂点。

**严重程度**：🔴 P0 — 直接导致用户流失

**建议**：在分析页和研究工作区添加"加入自选股"和"加入组合"一键动作。自选股应迁移到后端账户表，避免 localStorage 丢失。

### 6.2 🔴 P0：配色冲突 — 涨跌方向不一致

**问题**：全站使用 A 股"红涨绿跌"约定，但 `BacktestResultCard` 收益率正值用绿色 `#3f8600`、负值用红色 `#cf1322`，与全站方向相反。Dashboard 组合盈亏又用红涨绿跌。

**影响**：同一产品两种涨跌配色冲突，专业用户会困惑，非专业用户可能误读。

**严重程度**：🔴 P0 — 金融产品数据解读错误

**建议**：统一"红涨绿跌"约定，修正 BacktestResultCard 收益色。

### 6.3 🔴 P0：流式输出可访问性缺失

**问题**：聊天/讨论/研究的 SSE 流式区域没有 `aria-live` 属性，`StreamingText` 逐字渲染在 `prefers-reduced-motion` 下不退化为整段显示，屏幕阅读器会逐字反复播报。

**影响**：视障用户和开启减少动画的用户无法正常使用 AI 对话功能。

**严重程度**：🔴 P0 — 可访问性合规

**建议**：为流式区域加 `aria-live="polite"`，StreamingText 遵守 reduced-motion。

### 6.4 🔴 P1：首页信息过载

**问题**：今日概览同时展示指数、涨跌统计、行业排行、人气股、涨停池、自选股、决策收件箱 7 个区块。首屏还有 `LocalCapabilityBanner` 技术警告（"模型未配置/连通性未验证"）和系统统计卡（模型数/会话数/消息数）。

**影响**：新用户打开产品后不知道从哪里看起。技术警告条对非技术用户是"任务前障碍"。

**严重程度**：🔴 P1

**建议**：
- 首屏只展示市场概要（3 个核心指数 + 今日情绪），其余折叠
- 弱化/折叠 LocalCapabilityBanner（默认收起为"高级"）
- 移除或隐藏系统统计卡（对用户无意义）

### 6.5 🔴 P1：缺乏 AI-first 入口

**问题**：首页没有明显的 AI 对话入口。虽然有 `GlobalTaskEntry`（全局搜索弹窗），但需要点击顶部栏才能触发。AI 产品最核心的对话能力被埋藏。

**影响**：用户不知道可以和 AI 对话。

**严重程度**：🔴 P1

**建议**：在首页显著位置放置"问 AI"对话框，类似 ChatGPT 的首页设计。

### 6.6 🔴 P1：专业术语缺乏解释

**问题**：整个产品大量使用专业金融术语（TTM、MA、MACD、RSI、BOLL、VaR、ES、HHI、IC、ICIR、FACT/INFERENCE/MODEL_OUTPUT、canonical evidence、drift、hypothesis）没有 hover 解释。

**影响**：非专业用户无法理解页面内容。对自称面向"非技术投资者"的目标人群，这是真实门槛。

**严重程度**：🔴 P1

**建议**：为所有专业术语添加 Tooltip 解释，在知识库提供完整术语表。

### 6.7 🟡 P1：响应式缺失

**问题**：Chat 和 Discussion 页面使用左右固定 Sider 布局（260px + Content），移动端无折叠。气泡 `maxWidth: '70%'` 硬编码。大量内联 style 硬编码颜色，深色主题下不反转。

**影响**：移动端和深色主题用户体验差。

**严重程度**：🟡 P1

**建议**：Chat/Discussion 移动端折叠 Sider；气泡改用 AntD theme token。

### 6.8 🟡 P1：数据表交互不足

**问题**：市场面板（MarketMoversPanel/MarketThemesPanel）使用手写 HTML table，无列排序/筛选/分页。字体 8-10px 过小。选股器结果表也无排序交互。

**影响**：专业用户想按某列排序做不到；年长投资者阅读吃力。

**严重程度**：🟡 P1

**建议**：关键表迁移 AntD Table 以获得排序/筛选；字体放大至 12px+。

### 6.9 🟡 P2：研究工作区功能堆砌

**问题**：研究工作区同时承载行情快照、K 线、基本面、筹码、研究历史、讨论历史、论文历史 7 个维度。

**影响**：用户不知道应该先做什么。

**严重程度**：🟡 P2

**建议**：采用分步引导——先展示行情概要，再引导选择研究模式。

### 6.10 🟡 P2：策略实验室参数复杂

**问题**：回测参数表单 10+ 个参数（标的、日期、均线窗口、资金、佣金、滑点、印花税、最低佣金、最大回撤止损、基准）。

**影响**：非专业用户无法正确设置。

**严重程度**：🟡 P2

**建议**：提供"快速模式"（只填标的和日期）和"专业模式"（全部参数）。

### 6.11 🟡 P2：缺乏新手引导

**问题**：产品没有 onboarding 流程。用户可能永远发现不了深度功能（论文、回测、Alpha 因子、Swarm）。

**影响**：功能发现率低。

**严重程度**：🟡 P2

**建议**：添加 3 步快速开始引导 + 逐步介绍高级功能。

### 6.12 🟡 P2：K 线实现重复

**问题**：StockChart（hook 方式）与 StockAnalysis（内联 createChart）两套不同实现。指标子图只读不可与主图联动缩放。MACD 0 值被 `.filter` 丢弃破坏时间轴。

**影响**：维护分叉；专业用户无法联动缩放。

**严重程度**：🟡 P2

**建议**：以 useLightweightCharts hook 统一；子图与主图 time scale 联动。

### 6.13 🟡 P2：AI 能力分散在多个页面

**问题**：AI 研究能力分散在快速问答（chat）、多视角审查（discussion）、研究工作区（research/swarm）、个股分析（analysis）4 个不同页面。

**影响**：用户不知道应该用哪个 AI 功能。

**严重程度**：🟡 P2

**建议**：统一 AI 入口——在研究工作区提供"选择研究模式"。

### 6.14 🟡 P2：无面包屑导航

**问题**：ProLayout 未配置 breadcrumb，多层级研究页（研究工作区→深度报告→报告内）回退/定位靠左侧菜单。

**影响**：用户在深层页面难以定位。

**严重程度**：🟡 P2

**建议**：ProLayout 挂 breadcrumb 提升多层级定位。

### 6.15 🟢 P3：Chat 底部按钮语义含混

**问题**：Chat 页底部"运行回测"与"发送"两个并列按钮，初学者易混淆哪个耗额度。

**影响**：用户可能误触回测按钮消耗额度。

**严重程度**：🟢 P3

**建议**：分离"发送消息"和"运行回测"的操作区域，明确标注额度消耗。

## 6A. 组件级 UX 分析（子代理深度发现）

### 设计良好的组件（可作范本）

| 组件 | 亮点 |
|------|------|
| **GlobalTaskEntry** | 全局 AI 任务入口：搜索→选标的→6 类动作渐进式，带最近/已保存记忆，现代 AI 范式 |
| **ResultLayer / TaskPageHeader** | 结论→证据→方法三层显式分层 + 状态徽章 + aria-label，研究型产品结构清晰 |
| **MarketMoversPanel / MarketThemesPanel** | 每维独立标注可用性（SectionUnavailable）、绝不虚造数据、批量操作，金融可信度典范 |
| **NotificationCenter** | SSE 实时 + 桌面通知（含权限引导）+ 未读 Badge + 全部已读，完整闭环 |
| **Screening** | 自由文本输入（逗号/换行/空格/中文逗号分隔）、错误代码独立列出，表单设计样板 |
| **StrategySetup / AlphaTemplateCatalog** | 卡片式选择器 + "选择只更新本地表单，点击主操作才提交"，额度透明 |
| **凭据面板** | Fernet 加密、写入不回显明文、提交即清内存、"已配置/未配置"状态 Tag |
| **Login** | 两步邮箱验证码 + 倒计时重发 + inputMode/autoComplete 细节 |
| **全局 a11y 基建** | focus-visible outline、aria-label、prefers-reduced-motion、Suspense Spin |

### 设计有问题的组件

| 组件 | 问题 |
|------|------|
| **ChatMessageBubble** | 大量内联 style 硬编码颜色，深色主题不反转；气泡 maxWidth 70% 硬编码；11px 低对比元信息 |
| **StreamingText** | 逐字渲染对读屏/reduced-motion 不友好；无 aria-live；长文滚动抖动 |
| **Market 面板 Table** | 手写 HTML table，无排序/筛选/分页；字体 8-10px 过小 |
| **StockChart vs StockAnalysis** | 两套 K 线实现（hook vs 内联），风格不一致；指标子图只读不可联动；MACD 0 值被 filter 丢弃 |
| **Discussion Timeline** | 流式过程中无"当前发言 Agent"高亮进度条 |
| **Settings** | 9 个 Tabs 内容过载；外观 tab 只留一句"主题切换已移至顶部栏" |

### 深色主题兼容性问题

**全局通病**：Chat 页深色下气泡仍是浅灰底（硬编码 `#e6f7ff`/`#f5f5f5`），未用 AntD theme token。Discussion、StockAnalysis 等页面同样存在内联颜色不随主题反转的问题。

### 金融产品配色冲突

全站 A 股"红涨绿跌"，但 `BacktestResultCard` 收益率正值用绿色、负值用红色（与国际惯例一致但与 A 股相反）。**同一产品两种涨跌配色冲突**，务必统一。

## 8. AI Agent 能力分析

### 8.0 四大 AI 能力管线

FinQuant Hub 有 **4 条独立的 AI 能力管线**，全部走 FastAPI SSE、OpenAI 兼容协议：

| 能力 | 入口 | 编排 | Agent 数 | 流式 | 工具调用 |
|------|------|------|---------|------|---------|
| 单 Agent 聊天 | `/api/chat` | 单 Agent 工具循环 | 1 | SSE token | ✅ 13 工具 |
| 多 Agent 并行研究 | `/api/research` | 4 并行 + 主编收口 | 5 | SSE 进度 | ✅ 按角色白名单 |
| 多 Agent 讨论 | `/api/discussion` | 轮序串行 | 2-6 | SSE 逐 token | ❌ 无工具 |
| Swarm DAG 团队 | `/api/swarm` | YAML 声明式 DAG | 5-6 | SSE 进度 | ✅ 按 Agent 白名单 |

**统一骨架**：所有管线共享 `LLMClient`（OpenAI 协议）+ `ToolRegistry` 单例 + `DAGRuntime` + `model_router`。这是一套**自研轻量 Agent 框架**，非 LangChain/AutoGen。

### 8.0.1 13 个本地 Agent 工具

| # | 工具名 | 功能 | 类别 |
|---|--------|------|------|
| 1 | `get_stock_data` | 实时行情（现价/涨跌幅/PE/PB/市值/换手） | 行情数据 |
| 2 | `search_news` | 关键词财经新闻（6 源聚合） | 行情数据 |
| 3 | `calculate_indicators` | K 线技术指标计算（MA/MACD/RSI/KDJ/BOLL/ATR/VolMA） | 技术分析 |
| 4 | `verify_valuation` | 精确 PE/PB/P-FCF/股息率验算（十进制） | 估值计算 |
| 5 | `calculate_by_financial_rigor` | 任意金融表达式精确算术（白名单字符 eval） | 估值计算 |
| 6 | `screen_stocks` | 两阶段动量+价值选股（1-30 标的） | 估值计算 |
| 7 | `audit_report_data` | 报告数据点审计 + 准出/打回 | 估值计算 |
| 8 | `check_buffett_rules` | 巴菲特六关 checklist | 投研决策 |
| 9 | `adversarial_review` | 做空视角审查论点证据 | 投研决策 |

### 8.0.2 4 个基础研究 Agent 分工

## 10. 重构建议

### 10.1 信息架构重组

**当前问题**：6 个导航分组、18 个页面，功能分散。

**建议**：合并为 4 个核心工作流：

```
1. 发现（今日概览 + 选股器）
2. 研究（研究工作区 + 深度研究 + 多视角审查 + 投资论文）
3. 验证（策略实验室 + Alpha 因子）
4. 管理（持仓 + 预警 + 知识库）
```

系统工具（模型管理、MCP、设置）移至独立的"系统"菜单。

### 10.2 AI-first 入口设计

**当前问题**：AI 能力分散在 4 个页面。

**建议**：在首页添加统一的 AI 对话入口，AI 根据用户意图自动路由：

```
用户输入："分析贵州茅台" → 自动启动深度研究
用户输入："600519 和 000858 哪个好" → 自动启动比较工作区
用户输入："MA20 和 MA50 金叉" → 自动启动策略回测
用户输入："我的组合风险怎么样" → 自动启动风险分析
```

### 10.3 渐进式复杂度

**当前问题**：所有功能对所有用户可见，信息过载。

**建议**：实现三级复杂度模式：

- **简单模式**：只展示今日概览 + 快速问答 + 持仓（适合新手）
- **标准模式**：展示所有核心功能（适合普通投资者）
- **专业模式**：展示所有功能包括 Alpha 因子、Swarm、定时研究（适合专业用户）

### 10.4 新手引导系统

**当前问题**：没有 onboarding 流程。

**建议**：添加 3 步快速开始引导：

```
Step 1: "搜索一家你感兴趣的公司"（引导到研究工作区）
Step 2: "让 AI 为你分析这家公司"（引导到深度研究）
Step 3: "查看分析结果"（引导到报告阅读）
```

完成后展示"进阶功能"卡片，逐步介绍多视角审查、投资论文、策略实验室。

### 10.5 统一 AI 体验

**当前问题**：不同 AI 功能的交互模式不一致。

**建议**：统一所有 AI 功能的交互模式：

- 输入：自然语言 + 结构化参数（可选）
- 输出：流式文本 + 结构化结果 + 操作按钮
- 状态：进度条 + 预计时间 + 取消按钮
- 历史：可回溯 + 可对比 + 可导出
