# 实盘交易连接器与安全层设计评估

## 结论

Phase 9 不实现实盘连接器。当前系统无认证、授权、密钥隔离、不可变审计、订单幂等和券商沙箱验收，直接连接真实账户属于 **No-Go**。现有 `assess_trading_connector` 仅返回设计清单，`analyze_shadow_trades` 仅分析用户提供的模拟/历史成交；两者都没有网络、凭据、账户、资金或订单访问路径。

## 必须独立立项的前置条件

1. **身份与授权**：独立账户域、最小权限、读写凭据分离、短期令牌、密钥进入系统凭据库而非 SQLite/日志。
2. **交易前风控**：账户/市场/标的 allowlist，单笔和单日名义金额限制，持仓/可卖数量/T+1/价格笼子/交易时段校验。
3. **提交闸门**：下单前展示最终券商、账户、方向、数量、价格与最大损失，并由用户在最后一步明确确认；研究对话不能直接触发提交。
4. **幂等与状态机**：客户端幂等键、防重复订单、未知状态对账、部分成交/撤单/拒单状态，以及 kill switch 与 cancel-all runbook。
5. **审计与可恢复性**：追加式不可变审计、请求/响应脱敏、每日券商对账、时钟与交易日历校验、故障演练。
6. **合规与供应商审查**：确认目标司法辖区、券商 API 协议、行情/交易数据许可、适当性与留痕要求；这些结论当前均为 `unknown`。

## 建议阶段门

| 阶段 | 允许能力 | 准出条件 |
|------|----------|----------|
| A | 只读账户与持仓沙箱 | 凭据隔离、脱敏日志、权限测试 |
| B | 券商 paper/sandbox 下单 | 幂等、风控、对账、故障注入通过 |
| C | 极小额真实账户封闭试点 | 合规签字、双人审批、kill switch 演练 |
| D | 扩大范围 | 独立安全审计与持续异常监控 |

任何阶段都不得由 LLM 自主越过确认闸门。Phase 9 的准出范围止于本评估和无副作用的分析工具。
