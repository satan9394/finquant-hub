# PROD-062: 首屏、图表和长列表性能优化

> 状态：`[DONE]`  
> 阶段：Productization Phase 6

## 用户问题

产品路由已经懒加载，但构建仍提示大型共享 chunk，信息密集页面包含多个图表、长表格和重复请求。发布前需要先测量真实瓶颈，再做不改变金融结果与交互合同的最小优化。

## 目标行为

为 Dashboard 与三条核心旅程建立可重复的加载/渲染基线，识别首屏、图表和长列表的主要成本；只优化有证据的热点，并保证来源、数值、排序、空错状态与用户动作不变。

## 范围内文件

- Vite 分包配置、路由懒加载与直接影响首屏的共享组件
- Dashboard、研究、策略、组合中的图表和长列表渲染
- 相关 Vitest、Playwright 与性能证据脚本/文档
- `docs/ai/PRODUCT_CAPABILITY_MATRIX.md`、`docs/ai/EXEC_PLAN.md` 和本任务卡

## 明确非目标

- 不以隐藏数据、减少证据或降低金融精度换取分数。
- 不重写框架、图表库或数据层，不新增缓存服务。
- 不凭 bundle 警告做大范围重构；没有测量收益的改动不进入范围。
- 不修改架构或 `reference/`，不提交、发布、发送或下单。

## 数据与金融口径

- 懒加载、记忆化或虚拟化不得改变数据顺序、筛选、期间、来源和质量标记。
- 缓存只复用同一请求合同，不跨用户或把失败结果伪装为成功。
- 图表降采样若无既有明确合同则不实施。

## 交互状态

- 首屏：任务入口和当前状态优先可见，次要重组件可延后但有稳定占位。
- 图表：切换/缩放不重复做无关计算，文字摘要同步保留。
- 长列表：滚动和筛选保持可用，完整数据仍可访问。
- 错误/空：优化后错误、重试和 UNKNOWN 状态不退化。

## 可访问性要求

- 延迟内容不抢焦点，加载状态可读。
- 虚拟化或分段渲染不破坏键盘顺序和语义表格。
- `prefers-reduced-motion` 合同保持有效。

## 测试与浏览器验收

- 记录优化前后构建 chunk 与关键页面加载/交互测量，说明测量环境。
- 运行聚焦与完整 Vitest、Playwright、TypeScript/build、`git diff --check`。
- 真实浏览器验证 Dashboard 和三条核心旅程，桌面/窄屏无功能或可访问性回归。

## 文档同步项

- 更新能力矩阵的性能证据和仍存在的限制。
- 更新 `docs/ai/EXEC_PLAN.md` 和本任务完成记录。

## 完成定义

- 至少一个经测量的首屏、图表或长列表瓶颈得到可复现实质改善。
- 数值、来源、排序、空错状态、键盘和文字摘要不变。
- 构建与页面测量证据可重复，未以隐藏内容换取改善。
- 完整前端测试、构建、E2E 和浏览器验收通过。

## 回滚方式

恢复本任务的分包、延迟渲染或记忆化改动及对应测试；业务与数据合同保持不变。
