# PROD-054: 论文更新、观点漂移和研究待办统一时间线

> 状态：`[DONE]`  
> 阶段：Productization Phase 5

## 用户问题

论文 claim 的创建/核验、研究工作区更新时间和组合复盘待办已有各自入口，但用户无法按时间看清哪些观点变化、哪些证据需要复查、哪些任务已完成。分散状态也容易把本地派生待办误认为后端持久化研究事件。

## 目标行为

先盘点论文、研究工作区、已保存报告和本地复盘待办的真实时间字段与读取路径，形成最小只读统一时间线。每条事件显示来源对象、事件类型、发生/保存时间、当前状态和可达入口；无法恢复的历史不补造，前端派生与后端持久化来源明确区分。

## 范围内文件

- `frontend/src/pages/Thesis.tsx`、`frontend/src/pages/ResearchWorkspace.tsx` 或现有持续研究入口的最小复用点
- 现有论文、研究工作区、报告历史和本地复盘待办读取服务/类型及直接测试
- `docs/ai/PRODUCT_CAPABILITY_MATRIX.md`
- `docs/ai/EXEC_PLAN.md` 和本任务卡

## 明确非目标

- 不新增后台任务、轮询、通知规则、数据库表或事件总线。
- 不从当前状态倒推缺失历史时间，不把本地待办标成服务器事件。
- 不自动运行报告、漂移核验、预警、讨论或远端请求。
- 不重写论文/报告/研究工作区，不修改架构或 `reference/`。
- 不提交、发布、发送、下单或修改真实持仓。

## 验收

- 时间线只读取现有可恢复记录，每条记录有稳定 ID、来源类型、对象、时间、状态和原入口。
- 后端持久化、本地派生与当前计算状态有清晰标签；缺失时间或状态保持 UNKNOWN，不补默认值。
- 同一记录不会因跨入口读取重复展示；排序规则确定且可测试。
- 空、错、旧合同、桌面和窄屏状态可读；没有自动写请求或任务触发。
- 聚焦/完整前端测试、构建和浏览器真实记录验证通过；若修改后端则相关 pytest 与 Ruff 通过。

## 回滚方式

移除统一时间线入口与聚合读取逻辑；原论文、研究工作区、报告历史和本地复盘待办保持不变。
