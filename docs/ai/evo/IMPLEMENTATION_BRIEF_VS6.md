# IMPLEMENTATION_BRIEF — Vertical Slice 6：首启启动体验（浏览器等就绪 + 失败可自助）

> Orchestrator 第五阶段产物，2026-09-13。来源：**第二轮审计 A2 的已核实发现**（`AUDIT_R2_PARTIAL.md` 第 2、6 条；高度耦合，合为一个 slice）。

## 目标
让"第一次双击 start.bat 的人"不要被两件事卡住：
1. **不要在服务就绪前看到浏览器错误页**（现状：先开浏览器、后起服务）；
2. **失败时给非技术用户可照做的中文步骤**，而不是只丢终端命令。

## 用户场景
非技术中文投资者第一次双击 `start.bat`：前端首次构建需数十秒，脚本**立刻打开浏览器** → 用户看到 "This site can't be reached"，以为装坏了，关掉窗口 → 体验失败。
若环境缺失（没装 Python 3.12 / Bun），脚本只打印 `python -m venv`、`pip install` 等命令 → 目标用户无从下手。

## 当前问题（证据）
- `start.bat:108`（改前）`start "" "http://127.0.0.1:8000"` 在 `:110` 启动 uvicorn **之前**执行 → 首启必然先见错误页；QUICKSTART:40 仅以"稍后刷新"兜底。
- 失败分支（端口占用 / Python 环境 / 前端构建 / 服务启动）只给终端命令（改前 `start.bat:28`、`:125-130`、`:134-137`、`:117-118`）。

## 涉及模块
- `start.bat`（等待就绪 + 失败信息改写，仅 Windows 双击路径）
- `docs/QUICKSTART.md`（同步"自动打开浏览器"的新行为；原"浏览器可能早于服务打开"已过时）

## 不能破坏
- **成功路径行为不变**：前台仍由 uvicorn 阻塞运行、Ctrl+C 停止、端口固定 8000、备份段逻辑不动。
- 不引入新依赖；不删除任何文件；保留进阶命令（熟悉命令行的用户仍需要）。
- `start.bat` 必须保持 **CRLF**（LF 混入会让 cmd 解析崩溃）与 **UTF-8**（中文正确显示）。
- 不改 Docker 路径、不改其它脚本。

## 验收标准
1. 启动时**不再**在服务就绪前打开浏览器：改为后台等待 8000 可连接后再打开（带超时兜底，超时也打开一次并在窗口提示可手动访问）。
2. 窗口提示与实际行为一致（不再说"若暂未连上请刷新"）。
3. 四个失败分支均给出：**面向非技术用户的一句话原因 + 1-2-3 步做法 + 文档指引**，并保留"进阶"命令。
4. `start.bat` 保持 CRLF（LF-only = 0）与有效 UTF-8；无删除调用。
5. QUICKSTART 与新行为一致（自动打开 + 手动兜底）。

## 错误场景
- 后端启动极慢/失败 → 等待超时后仍打开浏览器一次，窗口提示手动访问与排查入口。
- 端口被占用 → 明确告诉用户"通常是上次没关干净"，给出关窗口/重启电脑两步。
- 缺 Python/Bun → 给出下载页与"勾选 Add python.exe to PATH"等要点 + QUICKSTART 对应小节。

## 测试要求
bat 无自动化测试框架，采用**实测**验收：
- 等待逻辑：临时端口起监听，验证轮询在就绪后立即返回；
- bat 语法：CRLF 复刻执行 launch 段（浏览器动作替换为输出）验证前台不被阻塞、后台等待器触发；
- 转义：验证 if 块内 `^)` / `^|` 渲染正确；
- 编码/换行：字节级校验。
由独立 Evaluator 复核上述实测证据与"成功路径零变化"。
