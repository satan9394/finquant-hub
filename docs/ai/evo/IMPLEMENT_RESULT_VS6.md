## 独立 Evaluator 质疑 → 修复记录
Evaluator 排除了唯一致命风险（实测 `start "" /b powershell ...` 后 **199ms** 后继命令即执行、cmd 仍在运行 → 前台 uvicorn 不被阻塞），但抓出 2 项必修缺陷：

1. **等待上限不是 90 秒（我的注释与卡片是假的）**：原实现按"循环次数"（90 轮）计时，而每轮 = 失败连接耗时 + sleep。Evaluator 实测单次失败连接 2038–2358ms（3 轮 9855ms ≈ 3.28s/轮）→ 90 轮 ≈ **295 秒**；若 SYN 被 DROP 可膨胀到 30 分钟以上。
   **修复**：改为**按截止时间**计时 —— `$deadline=(Get-Date).AddSeconds(90); while((Get-Date) -lt $deadline){...}`，sleep 改 500ms。注释同步更正为"按截止时间（本轮最多 90 秒）"。
2. **pip 失败分支文案自相矛盾**：`:install_backend` 的 pip 失败也 `goto venv_failed`，而该文案断言"通常是没有装 Python 3.12…请重装并重启"——可此刻 `.venv` 刚由本机 Python 3.12 成功创建，前提不成立，真实原因多为网络/磁盘/依赖下载。
   **修复**：新增独立 `:pip_failed` 分支（网络/磁盘原因 + 重试建议 + 进阶 pip 命令），`venv_failed` 只留给真正的 Python 缺失/venv 创建失败。
3. **（非阻断，双方独立发现同一处）文档锚点错位**：`:132` 原指向 QUICKSTART"第二步"（实为"双击 start.bat"），Python 安装图文在"你需要准备什么"。已改为后者；端口 FAQ 引用改为与文档标题逐字一致的 `提示“8000 端口已被占用”`。

## 结论（修复后）
消除首次双击 `start.bat` 的两个卡点：浏览器改为**等 8000 就绪后自动打开**（**按截止时间计最多 90 秒**，超时也打开一次）；失败分支按**真实原因**分流并给出面向非技术用户的步骤与文档指引。
