# IMPLEMENTATION_BRIEF — VS-36：同族"状态未按实体作用域"（Discover 检索 / Alpha 检索）

> 来源：**VS-32 的独立验收**（`EVALUATION_RESULT_VS32.md` 观察项 O1，`e2b9ff9` 归档）。**与刚验收的 F1（`Discussion` 详情，`27233a4`）是同一族**。

## 目标
把"**状态按实体（此处是查询词）作用域**"这一修法，用到同族的两处：
- `frontend/src/pages/Discover.tsx:49` 的 `nameSearchFailed`
- `frontend/src/features/alpha/AlphaResearchPanel.tsx:25` 的 `searchError`

**现症**：二者**未按查询词作用域**，只靠"**发起新请求时清一下**"来掩盖 ⇒ 换个查询词时，**上一词的失败信息会短暂挂在新词上**（与 F1 的"42 的错误原文出现在 43 上"同形）。

## 已有可复用的范式（**优先复用，不要另造**）
**VS-32 刚验收的修法（`27233a4`）**：**不给"切实体时清"**，而是**给状态补一个"它属于哪个实体"的归属**（`detailErrorId`），渲染处只认"属于当前实体"的状态 ⇒ ①不会闪一帧旧错误；②**保留了"这条错误是谁的"这一信息**。同族的 VS-29 `scopedDetail` 也是这个形状。

## 第一步（先做）
**先核实 O1 的两处是否确实未作用域**（读源码 + 给出**行号证据**），并**扫一遍这两处是否还有别的同族状态**（例如同类面板的 loading/空态是否也没作用域）。**若 O1 不成立（已作用域或无此问题），直接说明并给证据**——**本卡验收对象是"换查询词时旧词的失败会不会挂在新词上"，不是"是否动了代码"**。

## 理想行为
1. 换查询词 ⇒ **不得**出现上一词的失败原文（也不得出现它的结果）；
2. **当前词真的失败 ⇒ 必须显示它自己的错误**（**反向断言，少了它就是把修复做成"错误永不显示"**）；
3. 失败**可归因 + 可重试**（重试**真的重发**，以请求计数证明）；
4. 失败**不得**被渲染成"空"。

## 不能破坏
**VS-29 的三态契约**（`LoadFailureAlert.tsx` 是族内唯一实现处，`8d05556` 已验收）——**优先复用、不要另造三态判定**；这两处所在页面的既有测试全绿；既有断言**不得放宽**；不加依赖；**不 commit**。

## 验收标准
①**O1 核实 + 行号证据**（含"若不成立则说明"的出口）；②**换词不串**：断言换查询词后**无**上一词的失败原文/结果；③**反向断言**：当前词自己失败时**显示它自己的**错误；④**重试真重发**（**请求计数**证明，与成功解耦）；⑤**失败不伪装成空**；⑥既有测试全绿；⑦**鉴别力证明**：副本里退回修复 ⇒ 至少一条新用例变红；⑧门禁：相关 vitest + **串行** `bun run build`。
