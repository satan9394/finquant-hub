# IMPLEMENTATION_BRIEF — Vertical Slice 21：给重试加"整次调用总时长预算"

> Orchestrator 第五阶段产物，2026-09-11。来源：**R4 审计 D4 的 P2**（`RELIABILITY_REPORT_R4.md`），**编排者已逐项核码，D4 的数字正确**。

## 目标
一次 LLM 调用的**最坏静默等待时间必须是有限的、可预期的**——现在不是。

## 用户场景
用户在"深度研究"里等一个 Agent 出结果。上游限流/抽风时，界面**长时间没有任何反馈**，用户不知道是"还在努力"还是"已经卡死"，于是反复刷新或直接关掉。即便最终失败，用户也已经等了很久。

## 当前问题（编排者已核码，数字已验证）
`backend/app/services/llm_client.py`：
- `:25` `_MAX_ATTEMPTS = 3`（首次 + 2 次重试）；`:203` 每次尝试都是一次**完整 POST**；
- `:132` 单次 `timeout: float = 120.0`；
- `:32` `_RETRY_AFTER_MAX_SECONDS = 30.0`，`:79` 单次等待**上限** 30s，`:90` `_retry_delay_seconds` 优先用 `Retry-After`（受上限约束），缺失/非法时回落带抖动的指数退避；
- **⇒ 最坏静默等待 = 3×120 + 2×30 = 420 秒（7 分钟）**，而代码里**没有任何"整次调用"的总时长预算**：只有"单次尝试超时"上限与"单次等待"上限，**没有二者的聚合约束**。
- 参照：`chat_stream`（`:476`）**完全不重试**（`:487` 直接抛错）——**本卡不改它**（见"不在范围"）。

## 理想行为
给 `_post_chat_with_retry` 加一个**可配置的整次调用总时长预算**（默认值由实现者提出并说明依据），语义**必须可判定**：
1. 预算自**重试循环开始**计时。
2. **每次 sleep 之前**判断：若**已用时长 ≥ 预算** ⇒ **立即停止重试**，抛出**可行动**的 `LLMError`（**不得**悄悄变成成功或静默超时）。
3. 若**剩余预算 < 计划等待时长** ⇒ **把等待截断到剩余预算**（或直接停止，由实现者择一，但必须在结果文件写明并测到）。
4. **不得**截断"正在进行中"的那次尝试——单次 `timeout=120.0` 语义不变。
5. 由此得到的**可判定上界**：整次调用墙钟 ≤ **预算 + 单次尝试超时**（因为只在 sleep 前检查）。请把它写进 docstring。
6. 预算作为**构造参数**（默认值 + 可注入），使测试无需真的等待。

## 不能破坏（逐条）
- `_MAX_ATTEMPTS`、`_RETRYABLE_STATUS`、"非可重试 4xx 立即返回"、`Retry-After` 的尊重与 30s 上限（VS-10/VS-11 的成果）**均不得改变**；`_retry_delay_seconds` 的抖动逻辑不动。
- **网络类异常重试耗尽后抛 `LLMError`、状态码类返回最后一次响应** 这一既有分工不变。
- 错误文案仍须**可行动**（指出检查 API 地址/网络/供应商），并且**要能区分**"尝试次数用尽"与"总时长预算用尽"（否则日志无法诊断）。
- **不得**为迁就测试替身放宽异常处理（见 `AGENTS.md`）。
- 不加依赖；不改 API 形状；不删文件；不 commit。

## 验收标准（可判定）
1. **预算耗尽即停**：注入极小预算 + 使每次尝试必失败 ⇒ 断言**不再发起后续尝试**，且抛出的 `LLMError` 文案**指明是总时长预算耗尽**（可与"次数用尽"区分）。
2. **不超上界**：以**假时钟/注入的 sleep 记录**断言总等待 ≤ 预算 + 单次尝试超时。
3. **等待被截断**：构造"剩余预算 < 计划等待"（例如 `Retry-After: 30` 而剩余仅 5s）⇒ 断言实际等待**不超过剩余预算**。
4. **零回归**：预算充裕时行为与现状**完全一致**（尝试次数、`Retry-After` 生效、非可重试 4xx 立即返回、网络异常与状态码两类收尾分工）——给出既有 `test_llm_client` 全绿的原始输出。
5. `ruff check .` 干净。

## 错误场景
- 预算设为 0 或负数 ⇒ **不得**崩溃或变成"一次都不试"：要么拒绝该值（`ValueError`），要么按"至少完成首次尝试"处理——**择一并在结果文件说明**。
- 首次尝试就用掉全部预算 ⇒ 返回该次的真实结果/异常，**不得**因为"没预算了"而把它误判成失败。
- 上游返回 `Retry-After` 极大（如 3600）⇒ 仍受 30s 单次上限与总预算双重约束。

## 不在范围（明确排除，避免 scope 蔓延）
- **`chat_stream` 加不加重试**：流式重试有"重复已发出的 token"的风险，需单独设计，**本卡不动**（记为 NEXT）。
- **超时是否计入用量**：属计费口径问题，**本卡不动**（记为 NEXT）。

- 必须包含**鉴别力证明**：把新加的预算判断去掉（改副本、**不得**改被验文件）后，至少一条新用例应当变红。
