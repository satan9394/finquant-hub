# IMPLEMENTATION_BRIEF — Vertical Slice 22：失败不得伪装成空态（第二批：左栏列表与运行记录）

> Orchestrator 第五阶段产物，2026-09-11。来源：**VS-19 实现者主动报备的同类未修面**（`IMPLEMENT_RESULT_VS19.md` §4），**编排者已核码确认，并发现范围比报备更大（三处）**。

## 目标
把 VS-19 在首页"最近记录"卡片上建立的原则推广到**同一缺陷的其余三处显现面**：**空态只能代表"确实没有数据"；读取失败必须显式说出来。**

## 用户场景
**场景一**：用户在 `Chat` 左栏看不到任何会话，界面上写着"暂无会话"——但真实原因是**会话列表请求失败了**。用户会以为自己**从没保存过任何对话**（甚至以为自己误删了），而不是"网络/服务出了问题，可以重试"。
**场景二**：`Discussion` 左栏同理。
**场景三**：首页"研究运行"区块（`ResearchRuns`）在 `/dashboard/stats` 失败时同样退化为空列表，**没有任何错误提示**——而同页的两张"最近记录"卡片（VS-19 已修）此时**会**显示错误 Alert，**同页两种待遇**。

## 当前问题（编排者已核码，逐条给事实）
1. `frontend/src/pages/Chat.tsx:319`：`locale={{ emptyText: <Empty description={t('chat.empty')} /> }}` —— 左栏列表的空态**仅由"列表是否为空"决定**，**不引用** `sessionsFailed`。
   - 而 `Chat.tsx:81` 的 `sessionsFailed` **已存在**（`:94` 的 `.catch` 已置真），目前**只被深链提示用掉**（`:123-124`）。
2. `frontend/src/pages/Discussion.tsx:256`：同款结构；`roomsFailed`（`:59` / `.catch` 在 `:68`）同样**只服务深链提示**（`:84-85`）。
3. `frontend/src/pages/Dashboard.tsx:111`：`<ResearchRuns runs={researchRuns} />`，而 `researchRuns` 由 `stats?.recent_rooms ?? []` 推出（`:94`）⇒ **stats 失败时 `statsFailed` 为真、两张"最近记录"卡片显示 Alert，但这一块仍渲染空列表**。

## 理想行为
1. **Chat / Discussion 左栏**：列表请求失败时，在该列表位置渲染**与 VS-19 同款**的 `Alert`（失败文案 + 具体错误 + **可点的重试**，重试即**重新发起列表请求**）；**仅当请求成功且为空**时才显示"暂无会话/暂无讨论"。
2. **`ResearchRuns` 区块**：`statsFailed` 为真时**不得**只渲染空列表——同样给错误态（可与同页 Alert 同款）；`stats` 成功但确实没有运行时记录，才显示其空态。
3. 三处**共用同一种错误态组件/写法**（避免第三次再出现"同页两种待遇"）。
4. 文案走 i18n，**zh/en 同步**。

## 涉及模块
- `frontend/src/pages/Chat.tsx`、`frontend/src/pages/Discussion.tsx`、`frontend/src/pages/Dashboard.tsx`
- 可能新增/复用一个错误态小组件（若抽，请放在既有组件目录、遵循 `--fq-*` 令牌，**不引入依赖**）
- `frontend/src/i18n/zh.ts` / `en.ts`；对应测试

## 不能破坏
- **VS-19 的成果**：首页两张卡片的 `statsFailed ? statsAlert : …`、深链的**一次性提示**与**两种失败分开归因**（`deepLinkMissing` vs `deepLinkUnavailable`，**两个 key 不得混用**）、"不抢焦点 / 不清空既有选中 / 不为非法 id 发请求"（VS-16）。
- 各列表的**正常成功路径**与**合法空态**（成功且为空 → 仍显示"暂无…"）。
- `?prompt=`/`?topic=`/`?room=` 既有行为；`Chat`/`Discussion` 被 `StockAnalysis.tsx` 复用的用法。
- 不加依赖、不改后端、不改 schema；不删文件；不 commit。

## 验收标准（可判定）
1. **Chat 左栏**：mock `/chat/sessions` 失败 ⇒ 出现**错误提示 + 可点的重试**，且**不出现**"暂无会话"；点重试**确实再次发起**请求；成功且为空 ⇒ 仍显示"暂无会话"。
2. **Discussion 左栏**：同上（`/discussion/rooms`）。
3. **ResearchRuns**：mock `/dashboard/stats` 失败 ⇒ 该区块**不再**只渲染空列表（出现错误态或与同页一致的显式提示），**且不得影响** VS-19 已修的两张卡片的 Alert 行为。
4. **三处口径一致**：同一失败在三个位置给出**同一种**错误态形态（可用同款断言模式验证）。
5. **零回归**：VS-19 的 7 条新用例全绿；`?prompt=`/`?topic=` 既有用例全绿；i18n zh/en **一一对应**。
6. 门禁：相关 vitest 全绿 + `bun run build`（含 `tsc -b`）；**两者不要并行**；本机偶发 vitest forks worker 超时 → 原样重跑一次并如实记为环境噪声。

## 错误场景
- 列表请求失败 **且** 深链指向某 id ⇒ **两条提示都可能出现**（一个说列表读取失败、一个说该会话已不存在）——**不得**因为"已提示过"就吞掉另一条，也**不得**重复弹同一条。请明确二者关系并在结果文件说明（可接受：列表读取失败**优先**，不再弹"已不存在"，因为后者无法判定）。
- 重试仍失败 ⇒ 错误态保持、可再次重试，**不得**进入死循环。
- 失败后**恢复成功** ⇒ 错误态消失、列表正常渲染（**不得**残留错误态）。
- `stats` 成功但 `recent_rooms` 为空 ⇒ "暂无"正常显示（**不得**把合法空态误报为失败）。

## 测试要求
- 每个位置至少三条：**失败→错误态**、**成功且为空→空态**、**重试→恢复**。
- 必须给**鉴别力证明**：去掉新加的失败判据（改**副本**、不得改被验文件）后，至少一条用例变红；贴原始输出。
- **做变异/还原类验证时先声明窗口，或改用 `$env:TEMP` 副本**（本仓已发生过"并行读者把故意变异误读成真缺陷"的事故）。
- 临时产物放 `$env:TEMP`；**不要把门禁输出写进仓库目录**。
- 由独立 Evaluator 复核：①三处是否**真的**不再把失败渲染成空态；②重试是否**真的**重新发起；③是否**误伤**合法空态；④是否与 VS-19 口径一致。
