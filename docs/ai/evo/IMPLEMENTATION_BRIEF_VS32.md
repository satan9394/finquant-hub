# IMPLEMENTATION_BRIEF — VS-32：切房间时一并作用域"错误原文"（F1）

> 来源：**VS-29 的独立验收**（`EVALUATION_RESULT_VS29.md` 观察项 F1，`ab81dad` 归档）。编排者列为 NEXT，**建议单开卡**。

## 目标
`Discussion.tsx` 的**详情错误态未按房间作用域**：切房间后，右栏会**短暂显示上一个房间的错误原文**。

## 当前问题（**评估者已实测，直接采信**）
- `frontend/src/pages/Discussion.tsx:49-50` 的 `detailFailed` / `detailError` **未按房间作用域**——同文件里**只有 `scopedDetail`(:329) 做了作用域**。
- 评估者实测 `P10-OBSERVED`：`loading=false error=true staleErrorText=true` ⇒ **42 详情失败后切到 43，43 在途时右栏仍显示 42 的错误原文**。
- **这是 VS-29"不串台"修复漏掉的一维**：它作用域了**内容**与**加载态**，**未一并作用域"错误原文"**。同一处缺陷有多个维度时，修好其中几个，剩下的会以"**看起来已经修好了**"的形式留下来。

## 理想行为
切房间（`currentRoomId` 变化）时，**上一个房间的错误态一并作废**；新房间**在途**时右栏**不得**出现上一个房间的错误原文（也不得出现它的内容）。

## ⚠️ 最容易修错的一处（务必自证）
**不得把"清掉旧错误"做成"清掉一切错误"**：
- ✓ 42 失败 → 切 43（在途）⇒ **不显示 42 的错误原文**；
- ✓ **43 自己失败时，必须显示 43 自己的错误原文**（这是本卡的**反向断言**，少了它就是把修复做成了"错误永不显示"）；
- ✓ 42 失败**不切房间**时，42 的错误原文**仍要显示**。

## 涉及模块
`frontend/src/pages/Discussion.tsx`（主要）；必要的话其测试文件。**不要改 `LoadFailureAlert.tsx` 的三态契约**（VS-29 刚验收过，`8d05556`）。

- **负载抖动**：峰值下**连未变异的副本也会超时变红**，且同一用例同代码跨窗口可差 2–10 倍 ⇒ **不得据此改代码、更不得放宽断言或超时**；红灯若为 `Test timed out in 5000ms` 且落在**本卡未触及**的用例上，如实记噪声即可。
