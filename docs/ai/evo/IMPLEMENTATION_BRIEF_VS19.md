# IMPLEMENTATION_BRIEF — Vertical Slice 19：让"失败"与"没有数据"在界面上可区分

> Orchestrator 第五阶段产物，2026-09-11。来源：**R4 审计 A4 的两条 P2**（`PRODUCT_UX_REPORT_R4.md`），**编排者已核实证据链**。

## 目标
用户看到的"空"，必须**只**代表"确实没有数据"；**读取失败要显式说出来**。

## 用户场景
**场景一**：用户双击 `start.bat` 打开首页。`/dashboard/stats` 因瞬时故障失败——两张"最近记录"卡片显示"暂无会话 / 暂无讨论"。老用户以为**记录丢了**，新用户无法判断自己是否成功保存过任何东西。（**注意**：同一页面的"决策收件箱""市场/新闻"两区块**有** `Alert` 错误态 ⇒ 静默是**遗漏**而非设计约定。）

**场景二**：用户点首页"最近讨论"里的一条（该讨论已被删除，或房间列表尚未返回就被点击）→ 落到**空白默认视图**，**不选中、不提示、不报错**。这个体感与 R3 修复前的"点了落到空白新建界面"**完全相同**——"点了没反应"是放弃率最高的形态之一，且用户极难自我诊断。

## 当前问题（已核实）
1. **`frontend/src/pages/Dashboard.tsx:62`**：`catch { /* non-critical context */ }` 完全吞掉 `/dashboard/stats` 失败；`:107`/`:123` 的 `emptyText` 于是显示 `i18n/zh.ts:1118-1119` 的"暂无会话/暂无讨论" ⇒ **与真实空数据不可区分**。对照：同页 `:25`、`:90` 有 `Alert` 错误态。
2. **深链失效静默回落**：`Chat.tsx:85-95`（会话列表 `.catch` 静默）与 `:105-110`（不在列表则不 `setCurrentSessionId`）；`Discussion.tsx:59`（房间列表 `.catch(() => {})`）与 `:63-70`（注释与实现一致：不选中、不发请求、不提示）。

## 理想行为
1. **首页**：为 `stats` 增加错误状态；失败时在**两张卡片的位置**渲染与"决策收件箱"一致的 `Alert`（文案含"读取失败"与**重试**）；**仅当成功且为空**时才显示"暂无会话/暂无讨论"。
2. **深链失效**：**保持**"不抢焦点"的既有语义（不清空既有选中、不误跳），**只补一次性提示**——仅当 `requestedRoomId/requestedSessionId !== null` **且**列表已成功返回 **且**不含该 id 时，给出一次 `message.warning(...)`（如"该讨论已不存在，已显示当前列表"）。
3. **提示必须只触发一次**：与 `appliedRoomRef`/`appliedSessionRef` 同构（记住"已提示过的 id"），**否则会重演 R3 的"反复打扰"**——这是 A4 明确点出的风险。
4. 两处提示文案走 i18n，**zh/en 同步**。

## 涉及模块
- `frontend/src/pages/Dashboard.tsx`（stats 错误态 + 重试）
- `frontend/src/pages/Chat.tsx` 与 `frontend/src/pages/Discussion.tsx`（一次性警告）
- `frontend/src/i18n/zh.ts` / `en.ts`
- 对应测试

## 不能破坏
- **"不抢焦点"语义**：非法/不存在 id **不得**清空既有选中、**不得**为它发请求（VS-16 的成果，含后端 `user_id` 过滤兜底）。
- **`Chat`/`Discussion` 的 `appliedSessionRef`/`appliedRoomRef` 一次性守卫**；`?prompt=`/`?topic=`/`?room=` 既有行为。
- **同页其它区块的 `Alert` 错误态与成功路径**；Dashboard 的既有成功/空态文案。
- `Chat`/`Discussion` 被 `StockAnalysis.tsx` 复用的用法。
- 不加依赖；不改后端；不删文件；不 commit。

## 验收标准（可判定）
1. **stats 失败**：mock `/dashboard/stats` 失败 ⇒ 两张卡片区域出现**错误提示 + 可点的重试**（断言 testid 或文案），且**不**出现"暂无会话/暂无讨论"。
2. **stats 成功但为空**：仍显示"暂无会话/暂无讨论"（保持既有空态语义）。
3. **重试可用**：点击重试会**再次发起** `/dashboard/stats`；成功后被吞掉的错误提示消失、卡片正常渲染。
4. **深链失效提示一次**：`?session=<不在列表>` / `?room=<不在列表>` ⇒ 出现一次警告；**断言只被触发一次**（例如让列表再变一次、或重复渲染，确认不再提示）。
5. **合法性不被误伤**：`?session=<有效>` / `?room=<有效>` ⇒ **不出现**任何"已不存在"警告，且仍正常选中并加载该记录。
6. **零回归**：`?prompt=`/`?topic=`、`ChatBacktestRedirect`、`StockAnalysis` 复用路径既有测试全绿；i18n zh/en parity 一致。
7. 门禁：相关 vitest 全绿；`bun run build`（含 `tsc -b`）通过；**两者不要并行**。

## 错误场景
- 列表请求**自身失败**（不同于"不含该 id"）：**不得**弹"已不存在"（那是错误归因）——可静默（保持现状）或另给中性的"读取失败"提示，由实现者择一并说明理由。
- 重试仍在失败：提示保持、可再次重试，**不得**进入死循环。
- 空数据与失败**同时**可能：以"请求是否成功"为唯一判据。
- 深链 id 合法但**消息为空**：正常打开（空会话合法），**不提示**。

## 测试要求
- 复用现有手法：`Dashboard.test.tsx` 追加 stats 失败/空/重试三例；`ChatSessionDeepLink.test.tsx` 与 `Discussion.test.tsx` 各追加"失效提示一次"与"合法不提示"两例。
- 提示"只一次"的断言要**真能捕获重复**（让相关依赖再变一次，确认未二次提示）——避免写出"删掉守卫也全绿"的测试。
- 由独立 Evaluator 复核：①失败是否**真的**不再伪装成空态；②提示是否**真的只一次**且**不误伤合法 id**；③是否**清空**了既有选中（不得）。
