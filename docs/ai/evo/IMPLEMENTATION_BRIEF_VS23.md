# IMPLEMENTATION_BRIEF — Vertical Slice 23：给"整轮"对话加聚合等待上界（deadline）

> Orchestrator 第五阶段产物，2026-09-11。来源：**VS-21 实现者与验收者共同指出的裁决 (c)**，**编排者已核码并量出具体数字**。

## 目标
**"每次调用最多等 N 秒"不等于"用户最多等 N 秒"**——把 VS-21 的**单次调用**预算提升为**整轮**对话的聚合上界，并让"因超时提前结束"成为**显式结果**而非静默成功。

## 用户场景
用户在带工具的对话里提问。模型需要 5 轮工具调用（`max_rounds=5`）。若上游持续限流/抽风，**每一轮**都可能耗到单次预算上限——逐轮累加，用户**没有任何"最长等多久"的预期**，界面长时间无进展，用户不知道是在努力还是已经卡死。

## 当前问题（编排者已核码，数字已验证）
- `backend/app/services/llm_client.py:414` `chat_with_tools_loop(..., max_rounds: int = 5, ...)`，循环在 `:447` `for _round in range(max_rounds)`，**每轮**各调一次 `_post_chat_with_retry`（`:328`/`:378` 同族）。
- VS-21 之后**单次调用**的上界是 **预算(180s) + 单次尝试超时(120s) = 300s**。
- ⇒ **整轮最坏 ≈ 5 × 300 = 1500s（25 分钟），代码里没有任何聚合约束**（`max_rounds` 只约束**轮数**，不约束**时长**）。
- 调用方：`backend/app/routers/chat.py:189` 调用 `chat_with_tools_loop`。
- **顺带一项（VS-21 验收 NIT ①，同一文件同一主题，一并做）**：预算耗尽路径的错误**只带状态码、丢掉上游 body**（`_budget_exhausted_error` vs `_response_error` 带 `body[:300]`）⇒ 同一个 429 可能被误读成"预算太小"而非"账户额度/鉴权问题"。请补上 `response.text[:300]`（**沿用既有脱敏**，绝不泄露 api_key）。

## 理想行为
1. `chat_with_tools_loop` 增加**整轮截止**参数（如 `deadline_seconds: float | None = None`），**默认 `None` = 行为与现状完全一致**。
2. 每轮开始前检查是否已过截止：**已过 ⇒ 立即停止发起新的 LLM 调用**。
3. 传给每轮的**单次预算 = min(单次预算, 剩余整轮预算)**，使"整轮"不被单轮突破。
4. **"因截止提前结束"必须是显式结果**，例如返回结构里带一个明确标记/原因（`truncated_by_deadline` 之类），**绝不允许**把它伪装成"正常完成"——调用方/前端据此可如实提示"因超过总时长上限提前结束，以下为已完成的部分"。
5. **可判定上界**：整轮墙钟 ≤ **deadline + 单次调用上界**（因为只在轮间检查）。请写进 docstring。
6. 参数**可注入**，使测试无需真等。

## 验收标准（可判定）
1. **默认零回归**：`deadline_seconds=None` ⇒ 与改动前**逐项一致**（轮数、单次预算行为、错误出口），既有 `test_llm_client.py` 全绿。
2. **截止生效**：设定一个会被跨过的截止（用假时钟/注入）⇒ **不再发起新的轮**，且返回结果带**显式**的"因截止提前结束"标记（给出该标记的实际取值）。
3. **上界成立**：假时钟断言整轮墙钟 ≤ deadline + 单次调用上界。
4. **单轮不越界**：某轮开始时剩余预算小于默认单次预算 ⇒ 该轮实际使用的单次预算被**压低**为剩余值（断言实测值）。
5. **NIT ①**：预算耗尽错误文案**含上游响应的脱敏片段**；构造一个 429 + 特定 body 的用例，断言 body 片段出现在错误里、且 **api_key 不出现**（给出正反两例）。
6. **显式而非静默**：构造"截止恰好落在一次成功调用之后"的边界 ⇒ 结果标记与实际完成度**一致**（不得把"完成"标成"截断"，也不得把"截断"标成"完成"）。
7. 门禁：`pytest tests/test_llm_client.py`（及你改到的 chat 侧文件）+ `ruff check .`；**不要跑全量 pytest / `tests/test_api.py`**。
8. **鉴别力证明**：把新增的截止判断从**副本**去掉后，至少一条新用例变红；贴原始输出。

## 错误场景
- `deadline_seconds` 为 0/负/NaN/Inf ⇒ 与 VS-21 的 `total_budget_seconds` **同口径处理**（构造期 `ValueError`），保持一致性。
- 截止在第 1 轮之前就已过 ⇒ **不得**发起任何 LLM 调用，直接返回"未开始即截断"的显式结果。
- 最后一轮成功但已超截止 ⇒ 返回**已完成**的结果（不得误报截断）。
- 截止触发时**正在进行**的那次调用**不被中断**（与 VS-21 的"不打断进行中的尝试"一致）。
