# IMPLEMENTATION_BRIEF — Vertical Slice 28：让 chat 的"整轮截断"信号真的有消费方（或如实改正说法）

> Orchestrator 第五阶段产物。来源：**R5 审计 D5 的 🟠 项**（`RELIABILITY_REPORT_R5.md`），其事实**已由编排者逐条 grep 核实**。

## 目标
把 VS-23 声明的"**三通道**"**落实为真的**，或者**如实改正说法**——**不允许**"机制声明齐全、用户什么都没看到"这种中间态继续存在。

## 当前问题（**编排者已核实**）
VS-23 的验收标准写着"**显式、不可静默**"，其实现声称有三条通道（返回值 4 元组状态项 / `tool_loop_truncated` 事件 / SSE 正文与 `done` 标记）。D5 核实后发现：

- **通道②（事件）被丢弃**：`backend/app/routers/chat.py:179` 的白名单**只放行 `tool_completed`** ⇒ `tool_loop_truncated` **永远不会到客户端**（实测客户端事件序列只有 `token,done`）。
- **通道③（`done` 字段）无消费方**：`done.truncated_by_deadline` 在 **frontend 全库 grep 零命中**。
- ⇒ **实际只有正文前缀这"一通道"对用户生效**；而 `backend/app/services/llm_client.py:521-522` 的注释仍称"**事件通道同样显式**"——**注释与事实不符**。

## 理想行为（**必须二选一，并写清选了哪个**）
- **方案 A（接线）**：把该信号接到**用户可见处**——最小做法是让前端**消费 `done.truncated_by_deadline`**（例如在对话里给出"本次回答因超过总时长上限提前结束"的**持久提示**，而不仅是正文前缀）；若同时转发 `tool_loop_truncated` 事件，须**同步 `docs/API_CONTRACT.md`**（该文档的 chat SSE 契约刚在 `62acc50` 同步过，勿使其再次失真）。
- **方案 B（改正说法）**：承认只有正文前缀生效，**删除或改正 `llm_client.py:521-522` 的注释**，并把 `docs/API_CONTRACT.md` 中相关描述改为与事实一致（说明 `done` 的该字段**当前无消费方**、`tool_loop_truncated` **不外发**）。
- **无论选哪个**：`docs/API_CONTRACT.md` 与本仓注释**不得**继续宣称不存在的通道。**若选 B，"不加字段/不改前端"是允许的**——本卡要的是**诚实**，不是非要加功能。

## 涉及模块
- 方案 A：`frontend/src/pages/Chat.tsx`（或对话展示处）、`backend/app/routers/chat.py`（若转发事件）、`docs/API_CONTRACT.md`、i18n 双写
- 方案 B：`backend/app/services/llm_client.py`（注释）、`docs/API_CONTRACT.md`

## 不能破坏
- VS-23 的既有行为：正文前缀提示、`done.truncated_by_deadline` 字段本身、整轮 deadline 机制与**不传截止时的逐项零回归**；
- 既有 chat SSE 契约中**已被前端消费**的部分（`token` / `tool_call` / `done` 的既有字段）；
- 不加依赖、不改 schema；不删文件；**不 commit**。

## 验收标准（可判定）
1. **明确声明选了 A 还是 B**，并给出理由（写进结果文件）。
2. 若选 **A**：给出**实测**证明用户确实能看到（界面断言或响应断言），并说明**该提示是持久的**（不是 `toast` 一闪而过——用户回看时仍应知道这条回答被截断过）；若转发事件，`API_CONTRACT.md` 已同步。
3. 若选 **B**：给出**改动前后的注释/文档对照**，并**grep 证明**全仓不再出现"事件通道同样显式"这类与事实不符的说法。
4. **无论 A/B**：`grep` 证明 `API_CONTRACT.md` 的描述与**实际可观测行为**一致（若描述某事件/字段存在，则它必须真的能被客户端收到或被消费）。
5. 零回归：VS-23 的相关测试全绿；前端既有 chat 测试全绿。
6. **鉴别力证明**（选 A 时）：从**副本**去掉新接线 ⇒ 至少一条新用例变红。
7. 门禁：后端聚焦 pytest + `ruff check .`（**不要跑全量 pytest 或 `tests/test_api.py`——本机会挂**）；前端相关 vitest 全绿 + 串行 `bun run build`。

## 错误场景
- 截断**恰在成功之后**才越界 ⇒ 仍按**正常完成**处理，**不得**误报（VS-23 已有此边界用例）。
- 未截断的运行 ⇒ 前端**不得**出现任何"被截断"提示（构造正常完成夹具断言"无提示"）。

## 测试要求
- 临时/变异文件放 `$env:TEMP`；**不要把门禁输出写进仓库目录**；做变异/还原验证**先声明窗口**。
- 由独立 Evaluator 复核：①所选的方案是否**真的落地**（A 要能看到，B 要真的改掉说法）；②**是否又出现"声明了但没消费方"**（本卡的全部意义就在防这个）；③零回归。
