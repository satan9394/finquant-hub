### 变异敏感性判断（对 `"0"` / `"0.0"`）
**是，变异敏感 —— 退回 `seconds < 0` 这两个参数会挂。** 推理链：`float("0") == float("0.0") == 0.0`，旧判据下 `0.0 < 0` 为 `False` → 不进入 `None` 分支 → 返回 `min(0.0, 30.0) = 0.0`；而该参数集是"无效值 → 期望 `None`"的断言，故 `"0"` 与 `"0.0"` **各产生 1 个失败（合计 2 failed）**，恰为 29→31 的增量。这批参数因此真正钉住了"0 秒紧循环"这一缺陷，不是装饰性用例（该结论依赖参数集断言 `is None` 这一常规写法；本轮受环境约束未做实际回退实验，故标注为推理而非实测）。

1. **是否误伤合法极小正值（如 `Retry-After: 0.001`）？—— 不误伤，不算问题。** 判据是 `<= 0`，`0.001 > 0` → 通过 → `min(0.001, 30) = 0.001`，上游明示的正值仍被尊重，符合 RFC 9110 语义。
2. **残留观察（非阻断）**：修复后"0 秒紧循环"只在**恰好为 0** 时被消除；`Retry-After: 0.0001` 一类极小正值仍会被当作有效值（睡 0.1ms，近乎紧循环），且**同样绕过抖动**。这是"信任上游显式正值"与"防紧循环"之间的取舍，本修复未覆盖——若日后认为该风险实际存在，可加"低于某阈值（如 `< 0.05s`）视为无效"的下限，但那会改动语义，**不应在此次针对性修复里夹带**。此条不构成 REJECT，仅登记为可选后续项。
