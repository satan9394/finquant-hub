> 核心问题：**一个完全不了解这个项目的人，能否自己完成第一次成功使用？**

## 结论：当前最大 UX 缺口

### 缺口 1（最关键）：入门硬门槛有两道，且其中一道（Bun）在代码里被放在了"兜底逻辑之前"，使发行包的预构建兜底彻底失效

第一次成功使用的完整链路是：`装 Python 3.12 → 装 Bun → 双击 start.bat → 浏览器打开 → 点示例`。
其中**前两步要求一个非技术中文投资者在自己的 Windows 上安装两套开发者工具链**，而 QUICKSTART 给出的 Bun 安装方式是让用户打开 PowerShell 粘贴一行联网执行脚本（`docs/QUICKSTART.md:16-22`）——这与项目自身"避免 CLI/终端"的产品原则直接冲突。

更严重的是**代码顺序问题**：`start.bat` 在第 14-19 行就无条件检查 Bun，找不到直接 `goto fail`；而"复用已有前端产物、跳过构建"的判断在第 57 行才出现。也就是说——**即使发行 ZIP 里预置了 `frontend/dist`，没有装 Bun 的用户依然在第一步就硬停**，永远走不到"复用产物"这条路径。QUICKSTART 第 36 行告诉用户"已有页面产物会被复用"，这条承诺在当前脚本里是不可达的。

这是唯一会让"第一次成功使用"**彻底归零**的环节：其他所有问题（端口、模型未配置、行情为空）都还能降级使用，这里不能。

### 缺口 2：安装期指引完全在仓外文档，脚本内的首启消息已与文档的推荐路径分叉

应用内首启体验其实做得不错（见"值得保留"），但那要在**服务已经跑起来之后**才生效。而"下载 ZIP 之后怎么办"这一段，用户手里只有一份 Markdown：脚本不会告诉他先去读 QUICKSTART，QUICKSTART 也不会在他卡住时出现在屏幕上。同时 `start.bat:89` 仍在首启时提示「可用记事本填写 DEEPSEEK_API_KEY」，而 `docs/QUICKSTART.md:63` 已经改成「推荐直接在网页里配置」。**同一个项目对同一件事给出了两套首启指引**，非技术用户会误以为必须去编辑一个叫 `.env` 的文件。

### 缺口 3：端口冲突的恢复建议过重，第一建议是"重启电脑"

`start.bat:27-33` 在 8000 被占用时，给出的两条建议是「看任务栏有没有黑色窗口」→「重启电脑」。对非技术用户而言，"重启电脑"是成本极高的操作，却在文案里作为第二条、近乎首选的方案出现（QUICKSTART:94-105 同样如此）。而实际最常见的原因恰恰是"上一次的窗口还开着"，这个判断在 UI 上应该是第一条且最好自动完成。

## 发现的问题

### P0-1　Bun 硬性前置检查先于"复用已构建产物"逻辑，预构建兜底不可达

- **证据**：`start.bat:14-19`（`where bun` 失败即 `echo [错误] 未找到 Bun` → `goto fail`）；
  `start.bat:57`（`if not exist "frontend\dist\index.html" goto build_frontend` 才进入构建分支）；
  `docs/QUICKSTART.md:36`（"已有页面产物会被复用"）；`docs/QUICKSTART.md:155`（"start.bat 只在 dist 缺失或 package.json 更新时自动构建"）。
- **用户影响**：发行包即使带了构建产物，没有 Bun 的用户仍被硬停在启动脚本第一步，无法进入页面。文档承诺与脚本行为不一致，用户按文档理解会认为"我不用装 Bun 也能用"。
- **建议**：把 Bun 探测下移到 `:build_frontend` 分支内部（仅当确需构建时才要求 Bun）；发行包一律预置 `frontend/dist`，并在脚本顶部先用一句话说明"检测到已构建页面，跳过 Bun 检查"。这样"零工具链即可打开页面"成为默认路径。
- **优先级**：P0

### P0-2　要求非技术用户自行安装 Bun（含 PowerShell 粘贴联网脚本）

- **证据**：`docs/QUICKSTART.md:11`（"Python 3.12 与 Bun"列为必备）；`docs/QUICKSTART.md:16-22`（`powershell -c "irm bun.sh/install.ps1|iex"`）；`start.bat:16-19`（找不到 Bun 时的唯一出路是去 bun.sh 安装）。
- **用户影响**：目标用户是非技术个人投资者。让他在 PowerShell 里粘贴一条联网执行脚本，是整个首次使用过程中风险感最强、放弃率最高的一步；且失败后脚本只会让他"重新打开窗口再双击"，没有第二条路。
- **建议**：至少提供 (a) 预构建产物免 Bun 路径（见 P0-1）；(b) 面向非技术用户的图形化安装指引（下载 exe → 双击 → 一路下一步）；(c) 脚本检测到 Bun 缺失时，给出可复制的一行命令但**同时**说明"也可以找人帮忙装一次，之后就不用再装"。
- **优先级**：P0

### P1-1　Python 版本被严格钉死为 3.12，非 3.12 一律进失败分支

- **证据**：`start.bat:41`（`call py -3.12 -m venv`）；`start.bat:46-49`（`python -c "sys.version_info[:2] == (3, 12)"` 不满足 → `goto venv_failed`）；`start.bat:136-140`（失败文案只引导去装 3.12）；`docs/QUICKSTART.md:15`（明确要求 3.12.10 安装器）。
- **用户影响**：电脑上已装 Python 3.11/3.13 的用户（很常见）会看到一个"环境准备失败"的红色错误，而实际上他"已经装了 Python"。用户很难理解"装了但版本不对"这件事，第一反应是怀疑自己装错了。
- **建议**：失败文案先明确"检测到的是哪个版本、需要哪个版本"，并给出"若已装 3.13 也没关系，按指引再装一个 3.12 不会覆盖现有环境"这类安抚性说明；技术允许时放宽到 3.12+。
- **优先级**：P1

### P1-2　8000 端口被占用时，首要建议层级倒置（"重启电脑"排在前面）

- **证据**：`start.bat:29-30`（`[怎么做] 1) 看任务栏是否有黑色窗口` → `2) 还不行就重启电脑`）；`docs/QUICKSTART.md:98-105`（同样先给用户的是一串 `netstat` 命令，再让他去任务管理器对照 PID）。
- **用户影响**：用户面对一屏红字，被要求在任务管理器里按 PID 找进程——这是开发者操作。对非技术用户，这等于"我做不到"，于是直接放弃或真的重启电脑。
- **建议**：首选动作改为"先关闭所有黑色窗口再重试"并给出图示步骤；把 `netstat`/PID 段落标为「进阶（可跳过）」；长期可考虑由脚本在端口占用时**先自我识别是否为本项目的旧实例**并给出"是否结束它"的确认。
- **优先级**：P1

### P2-1　首启消息仍引导编辑 `backend\.env`，与文档新推荐的"站内模型管理"冲突

- **证据**：`start.bat:89`（`echo [配置] 已创建 backend\.env，可用记事本填写 DEEPSEEK_API_KEY，保存后重启。`）；
  `docs/QUICKSTART.md:63-70`（"推荐直接在网页里配置（不需要打开或编辑任何文件）"，且强调"配置后立即生效、无需重启"）；
  `start.bat:106`（启动横幅只说需要有效 key，未指向站内配置入口）。
- **用户影响**：非技术用户在启动窗口看到"用记事本填 key、保存后重启"，可能真的去翻目录找 `.env`，并因为把文件存成 `.env.txt`（QUICKSTART:72 专门警告过）而出现"填了还是不行"。这是本项目已修好的体验被脚本文案拖回去的典型情况。
- **建议**：把 `start.bat:89` 文案改为"启动后在页面左下/左侧 设置 → 模型管理 中填写 API Key，保存后立即生效，无需重启"；记事本路径降级为进阶提示。
- **优先级**：P2

### P2-2　Dashboard 与侧栏存在"入口名 → 目标页"不一致：点"聊天/讨论"落到"研究工作区"

- **证据**：`frontend/src/pages/Dashboard.tsx:94`（`navigate('/chat')`）、`:109`（`navigate('/discussion')`）、`:125`（footer 的"开始对话/创建讨论"按钮同样指向 `/chat`、`/discussion`）；
  `frontend/src/App.tsx:323-324`（`/chat` → `LegacyResearchRedirect mode="fast"`）、`:329`（`/thesis` → mode thesis）；
  `frontend/src/App.tsx:150-155`（重定向实现，跳转到 `/research?mode=…`）；
  `frontend/src/App.tsx:139`（`getMenuKey` 把 `/chat`、`/discussion`、`/thesis` 都归到 `/research` 高亮）；
  `frontend/src/App.tsx:74`（侧栏该分组的唯一子项是"研究工作区"）。
- **用户影响**：用户抱着"我要聊天/我要建讨论"的预期点击，地址栏变成 `/research?mode=fast`，侧栏高亮"研究工作区"。功能上没错（这是有意的路由收敛），但**用户会怀疑自己点错了**，且这个统一入口在侧栏里没有任何"聊天/讨论也在这里"的文字说明。
- **建议**：要么在 Dashboard 按钮文案上标注去向（如"开始对话（前往研究工作区）"），要么把侧栏"研究"分组下显式列出"快速问答 / 多角色讨论"两个子项，让模式选择在导航层可见。
- **优先级**：P2

### P3-1　发行脚本内硬编码维护者本机路径

- **证据**：`start.bat:15`（`if not defined FQ_BUN if exist "D:\Technology_application\NVM_Windows\nvm_a\v22.19.0\bun.exe" set "FQ_BUN=..."`）；`docs/QUICKSTART.md:123`（自认"脚本先找 PATH，再尝试维护者电脑的备用路径；其他电脑不需要创建这个备用目录"）。
- **用户影响**：不致命（对他人只是永不命中），但一旦有人在说明里看到或在脚本里读到，会产生"这个脚本是给某台特定电脑写的吗"的疑虑；对宣称"可开源分发"的定位属于噪声。
- **建议**：改为读取同目录下的可选 `local.paths.bat`（不存在则忽略），或直接删除该回退分支。
- **优先级**：P3

### P3-2　备份只提示不清理，把删除决策推给非技术用户

- **证据**：`start.bat:96`（`if($files.Count -gt 7){ Write-Host '[提示] 备份已超过 7 份，请按需保留后手动清理（回收站）多余文件。' }`——注释里明确写了"只提示不自动删除"）；`docs/QUICKSTART.md:161`（同样要求用户"按你的习惯移走或删除"）。
- **用户影响**：影响面小（7 个 .db 文件），但用户被要求自己去 `backend/data/backups/` 删文件——又一次把用户拖进了文件系统操作。
- **建议**：脚本内用回收站方式自动清理最旧备份（符合项目"删除一律进回收站"铁律），只保留 7 份，不再打扰用户。
- **优先级**：P3

## 值得保留的好体验

- **等后端就绪再自动开浏览器**：`start.bat:111-114` 用 TCP 探测轮询直到 8000 可连接才 `Start-Process`，且超时后仍尝试打开一次。这条直接消灭了新手最常见的"网页打不开/无法连接"首屏挫败，是本次审计中价值最高的一处改动。
- **面向非技术用户的错误文案结构**：`start.bat:27-33`、`:128-134`、`:136-145`、`:147-152` 统一采用「[错误] 是什么 → [怎么做] 分步编号 → [进阶] 命令行方案」，并且每条都把用户导向 `docs\QUICKSTART.md` 的具体章节。这是相当成熟的中文错误文案。
- **启动自动备份 + 文档化恢复流程**：`start.bat:91-103`（备份失败不阻塞启动、明确告知"数据仍可用"）配合 `docs/QUICKSTART.md:159-171` 的五步恢复说明。对"个人投资者的本地数据库"这类不可再生数据，这是正确的产品决策。
- **首页给了"不用先学会搜索"的入口**：`Dashboard.tsx:70-73` 定义了三张任务卡的"试一试示例"按钮（直接带 `600519` 进入分析/回测/组合），`Dashboard.tsx:92` 的 launchpad 卡片同时给出"这个功能回答什么问题/得到什么结果/示例"。对第一次打开、不知道该点什么的用户，这是最有效的引导。
- **能力状态诚实提示**：`Dashboard.tsx:28-39` 把模型能力明确区分"已配置未验证（CONFIGURED_UNVERIFIED）"与"未配置"，并配可跳转的按钮；`Dashboard.tsx:42-45` 的 `MarketSignalAvailability` 用 UNKNOWN 标签如实说明"暂无信号"，而不是伪造数字。与 QUICKSTART 第 54-61 行"没有 key 也能启动、哪些功能不需要 AI"的表格互相印证。
- **系统健康指示器常驻顶栏**：`App.tsx:219-229` 拉取 `/health`，`App.tsx:159-174` + `:253` 以 检查中/正常/不可用 三态呈现并可点击跳转设置。用户至少有一个"现在到底是不是好的"的客观信号。
- **不配置 AI 也能完成第一次成功使用**：`start.bat:106` 与 `docs/QUICKSTART.md:54-61` 共同保证了"先打开页面，再决定是否配置 AI"的路径成立，这是正确的产品分层。

## 未验证项

1. **LOCAL_ONLY 模式下是否真的没有登录墙**：`docs/QUICKSTART.md:50` 声明"此入口使用本机单人模式，不需要邮箱登录"，但 `frontend/src/App.tsx:363-390` 的 `AuthGate` 在未认证时会把用户重定向到 `/login`（`App.tsx:386-388`）。是否真无登录取决于 `useAuthStore.initialize()` 与后端在 `LOCAL_ONLY_MODE=1`（`start.bat:110`）下的行为，**未读 store 与后端实现，无法确认**。若本地模式认证失败，新手会在"文档说不需要登录"的地方撞上登录页——建议由主 Agent 指派验证。
2. **侧栏中文名与 QUICKSTART 措辞是否逐字一致**：QUICKSTART 说"研究 → 研究工作区""发现 → 涨跌停池""组合 → 组合与风险"（`docs/QUICKSTART.md:46-48`），代码里是 i18n key（`App.tsx:60-120`，如 `nav.research.home`、`nav.portfolio.home`）。**未读语言包，未验证**实际渲染文案，因此"A navigation 与文档对不上"这类判断本轮不作为发现项。
3. **新用户首屏是否"看起来是空的"**：`Dashboard.tsx:66` 并发请求 4 个接口，其中决策收件箱、最近会话、最近讨论对新用户必然为空（`Dashboard.tsx:25`、`:106`、`:121` 的空态文案未读取 i18n 实现）。空态措辞是否足够引导，**未验证**。
4. **默认语言与默认主题**：`App.tsx:412-413` 从 `localStorage` 读主题，语言由 `LanguageProvider` 决定；**未读 `i18n/LanguageContext`，未验证**默认是否为中文——若默认英文，对"非技术中文用户"是显著问题，需补验。
5. **README 作为第一入口的质量**：用户从 GitHub 下载 ZIP 后最先看到的很可能是 `README.md`（QUICKSTART 第 5 行有回链），但**本轮预算未读 README，未验证**它是否把"零工具链打开页面"作为首要路径。

---

**给主 Agent 的一句话**：本轮最大缺口不是应用内 UI（Dashboard 的首启引导做得相当扎实），而是**安装期的双重工具链门槛**——其中 `start.bat:14-19` 的 Bun 检查位置让"预构建产物免工具链"这条本可存在的兜底路径完全不可达，这是唯一会让新手第一次使用彻底失败的点。
