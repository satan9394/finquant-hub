## 1. 重做① 首页→研究连续工作面

### 1.1 目标与用户流程

把"首页提问 → 研究结果"连成单一工作面，消除当前"提问入口分散、提交后问题丢失、空右栏占宽、证据/枚举散在卡面"的产品割裂。

目标流程：提交后问题不丢 →（自动）搜索/识别对象 → 用户明确选"快速了解 / 生成报告"→ 进入研究，先见一句话结论与来源，再展开证据。

### 1.2 组件层方案（每步可独立 commit）

#### Step A — 收敛提问入口：单一 ⌘K 弹窗 + 顶部触发按钮
- **现状**：header CommandBar（App.tsx:223）与 Dashboard hero CommandBar（Dashboard.tsx:75）各自内嵌一个 GlobalTaskEntry，**每实例都向 window 注册 ⌘K**（GlobalTaskEntry.tsx:50-59）→ 同帧两个 listener 并存；Dashboard 是 `/` 路由页而 header 常驻，首页存在重复实例。
- **改法**：
  1. `GlobalTaskEntry.tsx`：把 ⌘K listener 从"每组件实例注册"改为**模块级单例守卫**（`useRef` 记已注册，或提升到 App 层单次注册 + 通过 DOM 事件/Context 触发当前实例弹窗）。**推荐**：⌘K 注册移到 `AppLayout`（App.tsx）一次，用一个 `openGlobalEntry` 状态 + ref 触发 header 内唯一 GlobalTaskEntry 打开；移除组件内自注册。
  2. Dashboard hero 的 CommandBar **不再内嵌可弹窗实例**——hero 只保留"输入框形态"的触发按钮（点击/回车触发同一全局弹窗并聚焦），即 hero 与 header 共用**一个**弹窗实例。实现：给 `CommandBar` 加 `triggerOnly` 变体（渲染触发按钮，onOpen 由 App 注入），hero 与 header 共用 App 层唯一 `GlobalTaskEntry`。
  3. **允许文件**：`App.tsx`、`components/CommandBar.tsx`、`components/GlobalTaskEntry.tsx`、`pages/Dashboard.tsx`（hero 改为 triggerOnly）、`app.css`（hero 触发样式沿用现有 command-bar--hero）、`tests/CommandBar.test.tsx`、`tests/GlobalTaskEntry.test.tsx`、`tests/AppNavigation.test.tsx`。
- **E2E 影响核对**：4173/8000 无对 ⌘K 或弹窗实例数的断言（grep 确认）；若未来用例要按，只新增不改既有。Dashboard E2E（dashboard.spec）断言 hero 内 `试用研究示例` 等按钮——**hero 触发入口改 triggerOnly 后必须保留 hero 区既有"试用 XX"launchpad 按钮组**（它们在 hero 下方 task-launchpad，非 CommandBar 内），仅 CommandBar 外观变，Dashboard.spec 需人工复跑确认无 `getByRole` 命名冲突。

#### Step B — CommandComposer 只任研究语境追问，提交携带对象+原问题

- **E2E 影响核对**：无 e2e 断言底部 composer（grep 无 command-composer 引用）；AppNavigation/Composer 测试为同步对象。

#### Step C — 空 AgentRail 默认折叠 / 按真实阶段展示
