# 非技术用户快速上手

FinQuant Hub 是运行在自己电脑上的投资研究工具，可以查行情、看指标、整理组合，并按需使用 AI 聊天和投研。先把页面打开，再决定是否配置 AI。

[返回项目说明](../README.md)

## 你需要准备什么

- 一台 Windows 10（1809 或更新版本）或 Windows 11 电脑，以及浏览器。
- 可用网络：首次安装需要下载项目依赖；之后查行情和调用 AI 也需要网络。
- Python 3.12 与 Bun（已附带 `frontend/dist` 页面产物时，启动**不需要 Bun**，见下方"提示没装 Bun / Python"）。Windows 双击路径**不需要 Docker**。

这两个工具只需安装一次：

1. **Python 3.12**：打开 [Python 官方 3.12 安装页面](https://www.python.org/downloads/release/python-31210/)，在 Files 中选择适合电脑的 Windows installer（常见电脑选 64-bit）。双击安装器，勾选 **Add python.exe to PATH**，再点 **Install Now**。该页面提供 3.12.10 传统安装器，并非最新的 3.12 安全版本；已有可用 Python 3.12 环境可直接使用。
2. **Bun**：打开 [Bun 官方安装说明](https://bun.com/docs/installation)，选择 Windows。按 Windows 键，搜索并打开 **Windows PowerShell**，复制官网提供的这一行，粘贴后按回车：

   ```powershell
   powershell -c "irm bun.sh/install.ps1|iex"
   ```

   安装完成后关闭这个窗口，再打开一个新的 PowerShell，输入 `bun --version`；能看到版本号表示已安装。项目使用 Bun 1.3 或更新版本。

## 三步上手

### 第一步：下载并解压

在 FinQuant Hub 的 GitHub 仓库页面点击 **Code → Download ZIP**。下载后右键压缩包，选择 **全部解压**，放到自己有写入权限的文件夹。

打开解压后的文件夹，直到看到 `start.bat`、`README.md`、`backend` 和 `frontend`。**不要直接在压缩包里运行**；如果没有 `start.bat`，请确认下载的是包含一键启动入口的版本。

### 第二步：双击 start.bat

双击 [start.bat](../start.bat)，保持弹出的窗口打开。它会检查所需工具、创建缺失的 Python 环境并安装项目已有依赖；需要构建页面时，也会按锁文件安装缺失的前端依赖。首次下载和构建可能需要几分钟或更久，取决于网速和电脑性能。

已有页面产物会被复用；没有产物或前端依赖说明更新时会重新构建。看到错误时窗口会保留原因和处理步骤，可在下方 FAQ 查找对应问题。

### 第三步：打开页面并开始使用

脚本会在服务就绪后**自动打开默认浏览器**，地址是 **[http://127.0.0.1:8000](http://127.0.0.1:8000)**（它会等一会儿，直到页面能打开为止，因此一般不会先看到"无法连接"）。如果浏览器没有自动弹出，或你想自己打开，请等启动窗口出现 `Uvicorn running` 后，手动访问上面的地址。

**本项目日常使用入口固定为 8000（Windows 双击 start.bat）。** 5173 仅用于 README 中的开发者或可选 Docker 路径，按本指南双击启动时无需切换端口。

看到首页后，可以先试试：

1. 点击左侧 **研究 → 研究工作区**，输入股票名称或代码（如 `600519`），从搜索结果打开标的，查看行情、指标和数据来源。
2. 点击 **发现 → 涨跌停池**，查看可用的 A 股榜单；点击股票代码可进入该标的的研究页。
3. 点击 **组合 → 组合与风险**，整理自己的组合记录。实时价格和盈亏展示依赖行情可用性。

此入口使用本机单人模式，不需要邮箱登录。使用期间保持启动窗口打开；结束时在该窗口按 **Ctrl+C**，如果询问是否终止批处理，输入 **Y** 并回车。下次再双击即可，关闭浏览器本身不会停止服务。

## 首次配置 AI（可选）

**没有有效 AI key 也能启动。** 启动不代表所有外部服务都可用：

| 能力 | 是否需要 AI key | 还需要什么 |
| --- | --- | --- |
| 股票搜索、行情、K 线、技术指标 | 不需要 | 网络、相应市场的数据源可用 |
| A 股筹码分布、资金流、龙虎榜、涨跌停池 | 不需要 | 数据源支持该股票与日期；筹码是模型推算，非交易所原始持仓 |
| 查看已保存的本地研究记录、整理组合 | 不需要 | 已有本地记录；刷新行情仍需网络 |
| AI 聊天、多角色讨论、AI 研究报告 | 需要 | 有效的模型配置、供应商权限/额度和网络 |

准备使用 AI 时，**推荐直接在网页里配置**（不需要打开或编辑任何文件）：

1. 双击 `start.bat`，等服务就绪后浏览器会**自动打开**（也可手动访问 <http://127.0.0.1:8000>）。
2. 左侧进入 **设置 → 模型管理**。若首页顶部提示"模型未配置"，点提示里的按钮可直接跳到这里。
3. 点 **新增模型**：选 **供应商**（如 DeepSeek），**名称**随意填写，**API Key** 直接粘贴你的密钥；**模型名**可点 **拉取模型列表** 选择，或手动填写。保存。
4. 在列表里点该模型的 **测试**，确认能连通；再点 **设为默认**，AI 聊天、讨论、研究报告就会使用它。

凭据以加密形式保存在本机，配置后**立即生效、无需重启**。本地安装会在 `backend/data/` 自动生成并长期复用一份密钥文件，因此**重启后不需要重新填写**；请像对待密码一样保管好整个 `backend/data` 目录，不要分享或提交到网上。

**进阶（可选，两种都行）**：也可以不通过网页，改用记事本编辑 `backend\.env`——把 `DEEPSEEK_API_KEY` 等号右侧的模板占位文字替换为有效 key（以及需要时的 `DEEPSEEK_BASE_URL`、`DEFAULT_MODEL`），保存后**重启**才生效。注意保存后文件名仍须是 **`.env`**，不要变成 `.env.txt`。

填过 key 只代表"已配置"，不代表已经连接成功。AI 返回鉴权、余额或模型错误时，检查供应商账号、额度和模型名称；无需为此重新安装整个项目。

## macOS / Linux，以及可选 Docker 路径

`start.bat` 只适用于 Windows。macOS/Linux 用户可使用项目现有的 Docker 路径：先准备并启动 Docker Desktop，或 Docker Engine + Compose v2，在终端进入解压后的项目文件夹，然后复制执行：

```bash
bash ./scripts/local.sh up
```

成功后打开 **[http://127.0.0.1:5173](http://127.0.0.1:5173)**。这个路径将 AI 配置放在项目根目录的 **`.env.local`**，而非 `backend/.env`；修改后再次运行 `up`。停止时运行：

```bash
bash ./scripts/local.sh down
```

Docker 路径的 Python/Bun 环境由镜像提供，无需在本机分别安装。Windows 也可以选 Docker，完整操作见 [README 的路径 A](../README.md#路径-a本地-docker可选容器化路径)。它是另一种本地运行方式；两条路径的数据位置不同，切换不会自动搬迁记录。

## 常见问题

### 提示“8000 端口已被占用”或“5173 已被占用”

**原因**：电脑上已有程序使用这个地址，可能是另一份 FinQuant。Windows 双击入口固定用 **8000**；Docker 默认用 **5173**，README 的开发方式也使用 5173。

**怎么做**：先查看是否已有启动窗口，正常关闭重复实例；不确定占用者时，打开 Windows PowerShell，复制对应一行：

```powershell
netstat -ano | findstr :8000
netstat -ano | findstr :5173
```

查看 `LISTENING` 行末尾的数字（进程编号），可在任务管理器“详细信息”中对照 PID 找到程序，确认用途后从该程序正常退出。Docker 占用可在 Docker Desktop 查看对应容器。不要结束不认识的系统进程；`start.bat` 不会自动杀进程或换端口。

### 没有 AI key，或 AI 一直报错

**原因**：没有有效 key、模板占位文字未替换，或服务商的权限、额度、模型、网络不满足要求。

**怎么做**：可以先用上表中的非 AI 功能；需要 AI 时按“首次配置 AI”操作并重启。行情失败与 AI key 是两类问题，补填 key 不会修复行情数据源。

### 行情为空，或显示 UNKNOWN / PARTIAL / UPSTREAM_ERROR

**原因**：可能是网络受限、上游暂时不可用、日期不在交易日、该标的不支持某项数据，或历史数据不完整。`UNKNOWN` 是未知，`PARTIAL` 是只有部分数据，`UPSTREAM_ERROR` 表示上游请求失败；这些是如实保留缺失的状态，不等于程序整体故障。

**怎么做**：先看卡片上的来源、时间和说明，检查网络，稍后重试，或换一个受支持的股票/交易日。历史龙虎榜席位、筹码峰等未提供的字段可能始终未知，不应把空白当成 0。

### 提示没装 Bun / Python，或安装、构建失败

**原因**：工具未装好、系统找不到安装位置，或首次依赖下载/构建没有完成。

**怎么做**：按开头的官网步骤安装，关闭旧窗口后重试。Python 要用 **3.12**，传统安装器应勾选加入 PATH；Bun 安装后用新窗口验证 `bun --version`，找不到时按官网的 PATH 说明修复。脚本先找 PATH，再尝试维护者电脑的备用路径；其他电脑不需要创建这个备用目录。

发行包已附带 `frontend/dist` 页面产物时，启动会直接复用产物，**全程不需要 Bun**；即使产物比 `frontend/package.json` 旧（打包或解压过程可能造成），脚本也只会提示"产物可能偏旧"并**照常启动**，不会要求你安装 Bun。只有产物**确实缺失**时，才会要求安装 Bun 并给出指引后退出。想确认自己属于哪种情况，看启动窗口是否出现"复用已有 frontend\dist"——该行会同时打印**所用产物的构建时间**，便于你判断看到的是不是旧界面。

如已有 Python 环境但提示缺模块，按启动窗口给出的 `pip install -r requirements.txt` 指引补齐现有项目依赖；前端失败则按窗口给出的 `bun install --frozen-lockfile`、`bun run build` 指引处理。保留报错文字便于排查，分享前去掉任何私密信息。

### 看到邮箱登录页（本机双击启动时不应出现）

**原因**：本机双击启动是单人模式，**不需要登录**。如果打开页面时后端还没完全就绪（或遇到瞬时故障），页面可能误判成"未登录"而跳到邮箱登录页；此时填邮箱点发送会得到「本地模式不提供邮箱登录」，因为本机模式**没有**邮箱验证码这条路。

**怎么做**：本机用户不需要登录。若页面显示"**正在连接本机服务…**"，说明它已经能识别这种情况，等几秒或点「**重试连接**」即可。若已经进到邮箱登录页，页面上方也有同样的说明和「重试连接」按钮；点它重新连接，成功后会直接进入应用。也可以直接刷新浏览器（地址仍是 <http://127.0.0.1:8000>）。若反复出现，先按上一条确认启动窗口里已出现 `Uvicorn running`，再重启 `start.bat`。

### 页面打不开，或重启后还是旧界面

**原因**：服务仍在准备、启动窗口已经关闭、浏览器地址用错，或复用了旧的页面产物。

**怎么做**：Windows 双击路径用 8000，Docker 默认用 5173。确认启动成功并刷新；更新了源码时，按下面的更新步骤主动重建页面。仅刷新浏览器无法替代重建。

### 怎样更新到最新代码，又保留自己的数据

**原因**：代码、安装环境和个人数据各自保存；直接覆盖整个文件夹容易混淆版本。

**怎么做（Windows ZIP 下载用户）**：

1. 按 Ctrl+C 完全停止旧服务。用资源管理器将旧项目的 **`backend/data` 整个文件夹**与 **`backend/.env`** 复制到另一个备份位置，保留原件。
2. 重新下载代码，**解压到新的文件夹**，保留旧项目作为退路。
3. 在新项目第一次启动前，把旧 `backend/data` 与 `.env` 复制到新项目相同位置。若目标已经有自己的数据，先另作备份，停止覆盖；这份指南不做两个数据库的合并。
4. 不要从旧目录复制 `.venv`、`node_modules` 或 `frontend/dist`。在新目录双击 `start.bat`，让它准备新版本的环境和页面。

如果原本通过 Git 获取项目，在停止服务、完成上述备份后，可在**项目根目录**打开命令提示符（资源管理器地址栏输入 `cmd` 并回车），执行 `git pull --ff-only`。遇到本地改动或合并提示时先保留文件、请熟悉 Git 的人处理，不要强制重置。拉取成功后，逐行执行以下命令，每行成功再继续：

```bat
backend\.venv\Scripts\python.exe -m pip install -r backend\requirements.txt
cd frontend
bun install --frozen-lockfile
bun run build
cd ..
start.bat
```

**更新后必须主动构建**：`start.bat` 只在 `frontend/dist/index.html` 缺失，或 `frontend/package.json` 更新时自动构建，不会逐个检测源码变化。Bun 不在 PATH 时先按官网修复，再执行上述命令。

Docker 用户的数据位于 Docker 数据卷；请按 [本地数据与隐私](LOCAL_DATA_AND_PRIVACY.md) 先备份，再更新代码并运行 `up`，不要套用 Windows 文件夹复制步骤。

### 自动备份与如何恢复

**自动备份**：每次双击 `start.bat` 启动时，系统会用 SQLite 的在线备份功能给数据库做一份**完整快照**，存到 `backend/data/backups/`，文件名带时间（如 `finquant-backup-20260913-083000.db`）。**备份不会自动删除**：累计超过 7 份时，启动窗口只会给出提示，请按你的习惯把多余文件移走或删除（送回收站），系统不会替你删。快照是**单一、自洽**的文件，已经包含尚未合并进主文件的最新数据，所以恢复时只需覆盖 `finquant.db` 一个文件。备份失败不影响启动（数据仍可用）。

**如何恢复**（磁盘故障、误操作或升级失败导致数据异常时）：

1. 按 Ctrl+C 完全停止服务。
2. 打开 `backend/data/backups/`，选一个最近、状态正常的备份文件。
3. 把 `backend/data/finquant.db` 备份到别处（留退路），然后用选中的备份文件**覆盖** `backend/data/finquant.db`。
4. 若 `backend/data/` 下还有 `finquant.db-wal` 或 `finquant.db-shm`，一并删除（它们只是未落盘的临时日志）。
5. 重新双击 `start.bat`。恢复后最近一次自动备份之前的记录会回到当时的版本。

**说明**：自动备份只包含数据库（组合、报告、记忆等），不包含 `.env` 里的密钥；密钥请继续按本文档妥善保管。

### 我的数据存在哪里？关掉窗口会丢吗？

**原因**：数据库文件、浏览器偏好与程序进程是分开的。

**怎么做**：Windows 双击路径的已保存记录在 **`backend/data/finquant.db`**（SQLite 数据库）中，关闭服务不会删除它；页面上尚未保存的输入不保证保留。部分偏好、自选等存在当前浏览器的本地存储中，换浏览器或清除网站数据可能使它们消失。Docker 使用独立的 `finquant-local-data` 数据卷，正常 `down` 会保留数据。备份前先完全停止服务，再复制整个 data 文件夹。

## 数据与隐私

此项目面向本机个人使用。Windows 入口只监听 `127.0.0.1:8000`，不会自动把数据库上传到项目维护者的服务器。

**本地保存不等于完全离线**：查行情会联系数据供应商；使用 AI 聊天、讨论或研究时，问题和相关上下文会发送给你配置的模型服务。主动启用的 MCP 工具等也可能访问外部服务。请自行决定输入哪些信息，并参考服务商的隐私条款。

妥善保管 `.env`、数据库、备份、报告和截图；共享电脑账号的人也可能访问这些文件。本指南不涉及公网部署。更完整的说明见 [本地数据与隐私](LOCAL_DATA_AND_PRIVACY.md)；开发者操作见 [README](../README.md)。
